# AI助手：RAG與受控Text-to-SQL

本輪把AI展示資料匯入獨立持久化資料區。六公司、144個AI延伸專案、3456個任務、4644份文件；資料基準日為2026-10-11，全部虛構。原有正式專案與附件保留，AI延伸案不混入正式任務樹。

## 使用

### 本地模型問答（隔離試用）

本機入口 `http://127.0.0.1:15176`，帳號 `yu`／`demo-yu`。AI副手選「入門文件：報到與教育訓練」，上方顯示 `pf-qwen3-rag:latest`。實際模型為 Qwen3-4B-Instruct-2507 Q4_K_M，使用 Ollama 0.40.6 與 RTX 4060 8GB；新API18006、模型11436均僅綁回環，雲端關閉。

可問「新人課程目前哪天上？」、勾歷史後問「新人課程原本哪天？為什麼改期？」、問「李小晴的月薪是多少？」驗證資料不足拒答。正式文件／附件資料集也可用同一模型回答，權限與來源檢查仍由API執行。

新副本與啟動器位於repo外 `../output/rag-starter-acceptance/local-model/`，使用`local-model.sqlite`、`files/`、`ai/`及獨立模型目錄；原15175測試資料與正式資料保留。執行該目錄的`啟動本地AI測試.ps1`可重開，不下載、不seed、不重設資料。

41個開發驗收案例包含37次真模型、2次無來源、1次完整工單規則、1次刻意斷線；另4項權限檢查通過。真模型暖機後中位數1.828秒；初次載入較慢。已核對引用、新舊版、附件、文件／問題誘導、斷線降級與恢復；這不是獨立測試或通用抗注入保證。

語意審閱仍有三處輕微限制：發卡應明示「預計」、不同專案不能推論沒有業務關係、聯絡窗口不能解讀成核准權。詳見[問答驗收報告](../../output/rag-starter-acceptance/local-model/問答驗收報告.md)。題庫HR在此副本用admin，未建立真正人資部門角色；峰曜帳號elaine也是admin，逐題報告記錄實際角色。

生成固定temperature=0、think=false、16384 context、最多1200輸出token。輸入以字元估算（非ASCII每字1.5、ASCII每字1；真模型實測約為實際token的1.7倍），依檢索排名只送放得下的完整段落，不從段落中間截斷；未送出的段落仍列在來源，處理紀錄寫明幾段未提供。最相關段落單獨就超限時不呼叫模型，回退檢索原文。送給模型的內容含資料基準日as_of。需模型回覆完成標記與正確結構，citations限本次提供來源並由後端再驗；資料不足則回固定拒答。引用有效不等於每句結論正確。單次連線5秒、讀取180秒逾時；模型閒置5分鐘可卸載。

重跑固定題庫（僅允許專用18006）：

```powershell
.\.venv\Scripts\python.exe deploy/check_local_model.py --report ../output/rag-starter-acceptance/local-model/new-run.json
```

加`--extended`會在此隔離副本建立／沿用虛構指令文件，並短暫改本公司模型設定測試斷線，finally恢復；請勿與手動問答並行。腳本只判斷來源範圍與格式，語意需另審。此次未合併main、未push、未部署正式PostgreSQL。

### 正式文件與附件索引（隔離版）

副手的「正式文件與附件（隔離）」資料集，來源為目前隔離資料庫中已上傳的文件各版本，以及可用、未刪除的附件。預設只查現行版本；明確勾選才查歷史。這是正式文件模組的索引流程，並未連線或部署到原本正式環境。

1. 在目前隔離環境的專案／任務文件區上傳文件，或在任務上傳附件。
2. 開啟副手，選「正式文件與附件（隔離）」及查詢專案。已啟用自動更新時，API運行中每10秒檢查變動，只處理新增／變動的文件版本或附件；管理者仍可按「更新文件索引」。無變動時不解析、不發布，索引時間不變。
3. 「查看索引狀態」列出當下可見來源版本的已索引／待更新／略過及原因、最近檢查與更新時間；計數包含歷史版本。一般使用者不能手動重建整家公司索引。面板開啟時每10秒更新狀態。
4. 輸入文件中的關鍵詞，預覽模型資料或送出查詢。引用標示文件／附件、版本與段落，可開啟該索引段落核對；不是原檔下載按鈕。
5. 上傳新版後，預設查詢立即排除舊版，等待自動或手動更新後才查得到新版。勾選「包含歷史版本」會搜尋已索引的新舊版本；來源及模型資料標示「歷史版本，請勿當作現行規定」，引用視窗顯示版本。取消勾選會清除舊對話／預覽／引用。
6. 歷史查詢不是找回刪除資料。已刪除附件／節點、撤回的負責人或協作者權限，各版本都重新核對。已顯示在畫面上的舊對話不會遠端回收，換範圍或重新查詢即可清除／重新驗權限。附件沒有版本鏈，不會製造歷史附件。

索引只建立衍生文字副本，不改原檔、版本、容量或任務。公司、專案及節點權限在每次查詢、預覽與開啟引用時從業務資料重新核對；不是只看角色。授權篩選在前六個搜尋段落的限制之前進行。正式來源尚無分級欄位，全部保守按機密交給本地閘道，不假稱已完成分級繼承。

支援 UTF-8 TXT／CSV、有文字層 PDF（最多30頁）、DOCX 本文／表格文字、XLSX 儲存格文字與儲存值。Excel保留儲存格座標、不重算公式或套用日期／金額顯示格式，工作表以檔案內部序號標示；Word不含頁首頁尾、圖片與文字方塊等進階版面。圖片、掃描PDF、加密檔、PPTX、ZIP及無可讀文字的文件會列為略過。Office不啟動應用程式、不跟隨外部連結；檔案10MB、文字20萬字，Office解壓後12MB／單個XML4MB上限，超限不只索引前半份。

以1200字、重疊150字分段，FTS5搜尋前六段；每公司最多500個來源版本。增量檢查比較來源metadata、檔案大小／修改時間／ctime與索引格式版本。新增第2版只解析第2版，第1版變成歷史標示不會重新解析；未變文字、段落與FTS詞項沿用。刪除來源只移除該來源的索引，不解析其他文件。不支援格式的略過結果也可沿用。

管理者在「查看索引狀態」看到最近一次成功發布的處理／沿用／移除來源版本數；一般成員不提供全公司統計。無變動時保留上次紀錄及時間。初次建置、舊索引格式升級需完整建立一次，之後增量更新。未變來源不讀取正文，但背景仍需掃描可見來源metadata及檔案狀態；若未透過系統改檔且刻意保留檔案狀態，可能無法偵測，查詢仍會核對SHA-256拒絕不符內容。

發布採SQLite backup複製衍生索引到暫存檔，只修改變動來源對應的資料列，完成後原子替換。因此是文件解析／索引記錄的增量處理，暫存發布仍需複製整個SQLite檔案。暫時讀檔或發布失敗保留舊索引並下輪重試；同程序同公司並行更新回409，下輪再檢查。每次讀取仍核對即時權限與來源fingerprint，候選段落再核對SHA-256。尚無完整版本差異比較、大量資料佇列或多程序協調。

本階段需同時設定 `PF_ACCEPTANCE_MODE=true`、`PF_AI_FORMAL_INDEX=true`，且只允許SQLite隔離環境。索引放在 `PF_AI_ROOT/formal-v1/`，按資料庫身分及公司分檔；原始檔依既有 `PF_ATTACHMENT_ROOT`。自動更新另需 `PF_AI_INDEX_AUTO_UPDATE=true`，三個開關預設皆關閉，未更動正式Compose設定。背景工作使用獨立Session及各公司現存admin來源權限，只讀業務DB；沒有admin的公司不自動建立索引。工作隨API啟停，啟動立即檢查；關閉等待當次建置結束，不建立Windows排程。僅支援單API程序，正式PG／多worker／大量資料佇列留後續。

`POST /ai/index/refresh`與既有查詢只增加摘要稽核，不記正文；自動更新只寫衍生索引，最近檢查／錯誤狀態保留於記憶體，重啟會重置。歷史問答與預覽傳 `include_history=true`；歷史引用也必須帶該選項，且重新驗權限。向量檢索、OCR與正式PostgreSQL部署尚未完成。

## 另一台電腦的Ollama

### 本地閘道第一版（隔離版）

目前文件問答與模型辨識分析種類統一經過本地閘道。雲端固定關閉，不能在請求中指定其他路由；完整工單及已選定的受控 SQL 直接由系統查詢，不把業務資料列送給模型。

在副手輸入問題後，按「預覽提供給模型的資料」，可以查看問題、檢索來源全文與資料等級。預覽本身不呼叫模型；模型未啟用時仍能查看「若啟用後」會提供的資料。它只呈現業務資料部分，不包含固定系統指令、JSON 格式要求或 HTTP 包裝。送出時重新檢查，資料、權限或設定若變動，實際內容可能與先前預覽不同。切換查詢範圍或修改問題會清掉舊預覽。

- 文件從既有 metadata 讀取公開／內部／機密等級，合併時採最嚴格值；自由問題至少內部。未標或未知等級從嚴視為機密，未做語意自動判級。這不代表正式公司／專案／欄位的分級繼承已完成。
- 檢索已按公司、角色、專案及版本過濾；閘道再驗公司與角色，資料範圍異常不送模型。一般成員的預覽也不能讀取人資預算。
- 每次模型呼叫重新驗證本地位址與非 cloud 模型名稱，直接改設定檔也不能略過。這只能約束 ProjectFlow 直接連線的目的地；Ollama 主機仍需自行禁止雲端轉送，不能把私有 IP 當作遠端主機不再外連的保證。
- 查詢回答中的「資料處理紀錄」區分未送出、已完成及曾嘗試但失敗。連線或引用驗證失敗仍回退檢索原文。
- `ai.query`／`ai.preview` 在既有稽核加入等級、原因、模型名稱與結果摘要，不保存問題／答案／來源正文或模型位址。稽核在查詢完成後提交，尚非送出前持久化日誌；未提供管理者專用查詢／匯出頁。

尚未完成遮罩／還原、混合與雲端政策、雲端供應商整合及正式附件分級繼承。文件／附件索引已在隔離版串接，正式部署仍待完成。真模型推論仍待安裝設定後另驗；閘道以模擬模型契約驗證出口與失敗處理。

### 設定方式

先在模型電腦安裝Ollama與適合該機器的聊天模型。Windows設定使用者環境變數 `OLLAMA_HOST=0.0.0.0:11434`、`OLLAMA_NO_CLOUD=1`，完全退出後重開Ollama；防火牆只允許ProjectFlow主機存取TCP 11434。兩台需有內網路由。

在ProjectFlow以管理者登入，展開助手底部「本地模型連線設定」，填 `http://模型電腦內網IP:11434` 與已安裝模型名稱，按「測試連線」，確認後勾選啟用並儲存。每家公司設定獨立，未設定的公司仍使用本地檢索。模型若在ProjectFlow同一台Windows上，Docker內請用 `http://host.docker.internal:11434`，不是容器自己的localhost。

連線測試檢查Ollama可达與模型已安裝，不代表生成品質已驗收。設定畫面只在本機管理者開放；只支援私有IPv4、localhost、host.docker.internal與IPv6 loopback，不接受公開端點、URL密碼、路徑、重導向或cloud模型名稱。實際請求不使用環境HTTP代理。請勿把本機Ollama再轉接雲端模型。

API契約依Ollama官方[Chat](https://docs.ollama.com/api/chat)、[結構化輸出](https://docs.ollama.com/capabilities/structured-outputs)與[網路／本地模式設定](https://docs.ollama.com/faq)。採文字搜尋RAG（中文雙字詞FTS5與BM25），目前不需要embedding模型；向量檢索與OCR尚未實作。正式文件／附件索引已串接隔離版，尚未在正式PostgreSQL環境部署。

入門資料匯入器另支援有文字層的PDF、Markdown及TXT；正式文件索引可在隔離版自動更新，也保留管理者手動更新，不支援掃描PDF的OCR。

## 資料與權限

- `projectflow-formal_ai_data`是獨立Docker volume；`dataset-v1/`中每公司一個唯讀SQLite，`settings/`保存每公司模型設定。查詢無權寫入AI資料庫，設定操作與查詢摘要會寫入既有稽核（不記問題全文／模型答案／位址）。
- 公司由登入session決定，API不接受任意company_id。文件依allowed_roles過濾，成本月報僅admin/project_owner；其他角色可能沒有可見文件。分析限admin/project_owner。
- 這些是公司層級展示專案，不是正式節點，所以不使用正式node_id或假裝繼承其ACL。查詢前依公司、角色、所選AI專案過濾；引用原文再次驗權限。切公司、離頁、登出清除對話並中止前端請求。
- 只檢索現行版本，全文檢索前六筆。引用編號必須出自檢索結果；這是引用有效性檢查，不保證模型每句結論正確。模型不可達、格式錯誤或引用不符時回退原文並提示。
- SQL是程式內固定白名單、參數化、read-only連線，另有authorizer、執行步數與200列上限。公司實體分庫，專案篩選用受控CTE；不接正式業務DB分析。
- 金額為未稅TWD整數。expenses是已入帳成本；訂單是採購承諾，兩者不重複相加。不良率合計分子與分母。逾期為due_date早於基準日且狀態非done。

## 匯入與重現

### 新入門資料（starter-v1）

來源包在`deploy/rag-starter`。先在獨立目錄驗證：

```powershell
$env:PYTHONPATH = 'api'
.\.venv\Scripts\python.exe deploy/check_rag_starter.py --destination ../output/rag-starter-local-ai --report ../output/rag-starter-evaluation.json
```

檢查器匯入後用32題核對權限、版本與必要來源；Q31使用明確的完整工單模式。它不呼叫模型、不測模型答案正確率。29題有指定來源，其餘3題屬資料不足或未授權；拒答語意仍需模型啟用後另驗。

正式Docker引擎正常、先完成備份與部署更新後，才執行：

```powershell
docker cp deploy/rag-starter projectflow-formal-api-1:/tmp/rag-starter
docker exec projectflow-formal-api-1 python -m app.ai.import_cli /tmp/rag-starter --dataset starter-v1
```

只新增`ai_data/starter-v1`，不改原`dataset-v1`或PostgreSQL。若不同版本已存在會拒絕覆蓋，不能刪原資料來繞過；需另外規劃更新流程。同內容重跑及同時匯入可安全完成。這些命令不是本次已部署的證明。

### 舊資料（dataset-v1）

資料包位於workspace的 `ai-demo-data/pack`（另有ZIP與生成器）。先備份正式DB與附件，再更新API/web映像。不可重設DB或重新seed正式環境。

```powershell
docker cp ../ai-demo-data/pack projectflow-formal-api-1:/tmp/ai-pack
```
