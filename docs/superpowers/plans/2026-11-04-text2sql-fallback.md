# TEXT2SQL-FALLBACK：資料分析被拒答時的分層降級（短規格與計畫）

依使用者 2026-11-04：討論 Text2SQL 拒答太多會不好用後，指示「針對這三個目標幫我做出來」：①做出分層降級、②用題庫量出成效、③用測試證明降級回覆不會出現公司數字。規則逐條確認如下（規則 4 選「只回答系統怎麼用」；規則 7 題庫先給使用者看；開新分支；其他照 AI 建議的預設）。

- 範圍：AI 助手「資料分析」（`mode: 'sql'`，`dataset-v1`）。主要檔案：`api/app/ai/service.py`、新模組 `api/app/ai/fallback.py`、`web/src/components/CopilotPanel.tsx`。
- 流程：WORKFLOW §14 精簡流程＋§14.1 展示收斂。分支 `feature/text2sql-fallback`，做完給使用者看，**不合併、不推送**，等使用者確認。
- 底線：**降級時降的是功能，不是正確性。** 只有真的執行了白名單模板，回覆才能出現公司資料的數字或名稱。

## 已確認的規則

| # | 規則 | 決定 |
|---|---|---|
| 1 | 不支援的條件 | 四類：時間（上週、上個月、9 月、今年、下個月…）、特定對象（人名、部門名、專案名、廠商名）、狀態（已完成、已結案…）、排序比較（前三、最高、比較…）。對象名稱從該公司的展示資料讀取，不寫死 |
| 2 | 最接近的分析 | 人寫好的「關鍵字 → 分析」對照表，最多 3 個；本機模型開啟時再併入模型建議。一律要使用者按下才查，並標明「不含『上週』條件」 |
| 3 | 預寫回覆 | 依 5 類（工作進度、錢、供應商、品質、風險）各一段說明與 2～3 個快捷題，白話、基層看得懂 |
| 4 | 聊天模式 | 只回答系統怎麼用（能查什麼、怎麼問）。**全部是預先寫好的模板，由規則挑選，不經過模型** |
| 5 | 不進聊天模式的問題 | 有數量／金額／比例／清單字眼，或部門、專案、廠商、人名等資料詞，一律走查詢或建議 |
| 6 | 拒答紀錄 | 只記錄拒答類型與條件類別（例如 `condition:time`），**不記原文**，沿用既有「不存提問原文」的隱私設計 |
| 7 | 題庫 | `deploy/ai-demo-data/fallback-eval/questions.json`，30 題四組（換說法 10、多加條件 10、使用說明 5、危險刁難 5）。使用者確認後定稿，量測期間不可修改 |
| 8 | 成功定義 | 換說法／多加條件：正確分析出現在建議前 3 名且未自動執行；多加條件另須說對條件類別；使用說明：回說明模板；危險刁難：不執行、不建議、不出現公司數字。現行版本與新版跑同一題庫對照 |
| 9 | 量測條件 | 本機模型關、開各量一次（模型可用時） |
| 10 | 底線測試 | ①降級與說明回覆的內容不含任何公司資料值；②假模型回「大約 5 件」等內容時被擋下；③說明模板產生時不讀公司資料 |
| 11 | 流程 | 新分支、不合併不推送；工作區既有的未提交檔案不動 |

## 回應種類（`kind`）

既有：`sql`（執行模板）、`query_suggestion`（模型建議）、`unsupported`。新增欄位不破壞既有前端：

| 情況 | `kind` | 內容 |
|---|---|---|
| 整句符合 | `sql` | 不變 |
| 核心分析對、多了不支援條件 | `fallback` | `fallback.reason='condition'`、`conditions`（類別與原字）、`suggestions`（≤3，含 `query_id`、`label`、`omits` 說明） |
| 對不上但看得出主題 | `fallback` | `reason='topic'`、該類說明與 `suggestions` |
| 使用說明或無關問題 | `help` | 預寫模板，`suggestions` 為快捷題 |
| 危險、跨公司、寫入、無此資料 | `unsupported` | 固定說明，無建議 |

使用者按建議 → 前端以 `query_id` 送出（既有通道），照舊執行模板。
