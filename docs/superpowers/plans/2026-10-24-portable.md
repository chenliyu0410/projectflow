# PORTABLE：可攜展示包（短規格與計畫）

依人類 2026-10-24「之後要包成一包，放在別人的電腦上跑」「先寫打包成可攜版的短規格給我確認」。依 WORKFLOW §14（精簡流程）；**本文件核准前不寫程式**。

## 展示目標

把專流（含 AI 副手、文件樣板）做成一個資料夾（壓縮檔），複製到另一台 Windows 電腦、解壓縮、雙擊「啟動專流.bat」，就能在那台電腦的瀏覽器用 `yu`／`demo-yu` 登入，照[AI副手示範題目](../../ai-demo-questions.md)走完展示。對方電腦**不用裝 Python、Node、Docker、Ollama**，也不用連網。

## 現況與問題（2026-10-24 實查）

目前 15176 隔離版只能在這台電腦跑，原因：

| 項目 | 現況 | 搬到別台會怎樣 |
|---|---|---|
| Python | `.venv` 指向 `C:\Users\User\.cache\codex-runtimes\...` 的 Python 3.12 | 找不到 Python，後端起不來 |
| Ollama | 用 `%LOCALAPPDATA%\Programs\Ollama` 的安裝版 0.40.7，會自動更新 | 對方沒裝就停；版本可能不同 |
| 問答模型 | `pf-qwen3-rag` 由另一個專案資料夾裡的 GGUF（`.codex/worktrees/receipt-role3/.../Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf`）建立；在隔離版 `ollama-models/manifests` 找不到它的設定檔 | 直接複製資料夾可能沒有問答模型 |
| 網頁 | 用 Node 跑 Vite 開發伺服器 | 多一個 Node 執行檔、啟動慢 |
| 資料 | 隔離版 SQLite 有 57 個專案，多數是 E2E 殘留（如「TP-A 375 d1df…」） | 展示時很難看 |
| 展示專案 | 「增量索引展示」「OCR 示範」「遮罩示範」是測試或手動建的，沒有可重跑的建立腳本 | 無法重建乾淨資料 |
| 大小 | `ollama-models` 11GB，含未使用的 gemma4 | 包太大 |

## 範圍

### 1. 包裡帶什麼

```
ProjectFlow-Portable-<日期>/
├─ 啟動專流.bat / 停止專流.bat / 還原展示資料.bat
├─ 使用說明.txt（含帳號、示範題、常見問題）
├─ runtime/
│  ├─ python/        可攜式 Python 3.12（python-build-standalone，uv 取得）＋鎖版依賴（requirements.lock＋requirements-ocr.lock）
│  └─ ollama/        Ollama 0.40.7 執行檔與 GPU 函式庫（CUDA 12／13、ROCm、Vulkan、CPU），不含會自動更新的系統匣程式
├─ app/
│  ├─ api/           後端程式（不含 tests、.pytest_cache）
│  ├─ web/           前端 build 結果（dist，不帶 Node）
│  └─ serve.py       單一程序：/api 掛後端、其餘回前端頁面
├─ models/
│  ├─ qwen3-4b-instruct-2507-q4_k_m.gguf（約 2.4GB）＋ Modelfile
│  ├─ bge-m3（約 1.2GB）
│  └─ ocr/（繁中辨識模型，約 11MB，附 SHA-256）
├─ seed/             乾淨展示資料（見第 2 點），還原用，唯讀
├─ data/             執行中的資料庫、附件、AI 索引（第一次啟動時由 seed 複製）
├─ logs/
└─ licenses/         Qwen3（Apache-2.0）、bge-m3（MIT）、Ollama（MIT）、RapidOCR（Apache-2.0）等授權
```

預估解壓後約 7GB（Ollama GPU 函式庫 3.1GB、模型 3.6GB、Python 約 0.4GB）；壓縮後約 6.5GB，用 zip64 或 7z。

**不帶**：Node、`web/node_modules`、測試、`.git`、隔離版 SQLite 與其附件、gemma4、任何 `.env` 或真實密碼。

### 2. 乾淨資料怎麼準備

由打包腳本從空資料庫**重建**，不複製目前的隔離版資料庫：

1. 建空 SQLite，migration 升到 `20261012_0019`，匯入 repo 的展示資料包（`deploy/demo-data`，6 家虛構公司、39 個專案、約 80 個帳號，密碼 `demo-<帳號>`），再升到最新版本。
2. 匯入 AI 入門教材（`deploy/rag-starter`，24 份，`starter-v1`）。
3. 以 API 建立 AI 示範專案並上傳固定的虛構文件：「增量索引展示」（報到地點第 1 版三樓、第 2 版五樓）、「隔離索引展示」（設備申請流程）、「OCR 示範（虛構）」（圖片公告、掃描 PDF）、「遮罩示範（虛構）」（〈配方成本試算.txt〉、合作夥伴「青禾原料行」）。這些文件從隔離版現有附件中取出內容相同的檔案，放進 repo 的 `deploy/portable/demo-docs/` 當固定素材。
4. 毛研食品加入三份文件樣板範例。
5. 建好 AI 索引（含向量），讓第一次啟動不用等重建；AI 政策維持預設（全本地、雲端未設定）。
6. 檢查：專案清單沒有測試殘留名稱；示範題 D01–D21 用到的專案、文件都在；資料夾內找不到 `C:\Users\User` 這類本機絕對路徑。

成果放到 `seed/`。`還原展示資料.bat` 會先停服務，把 `data/` 改名備份，再從 `seed/` 複製一份新的。

### 3. 啟動與停止

- `啟動專流.bat` 依序：
  1. 檢查 Windows 10／11 64 位元、可用磁碟空間 ≥ 5GB、記憶體（16GB 以下時提醒可能變慢）、連接埠 15190（網頁）與 11437（模型）沒被占用。
  2. 偵測顯示卡：NVIDIA、AMD 或只有 CPU，顯示「AI 會用顯示卡／CPU 執行，CPU 模式一題可能要 30 秒以上」。
  3. 第一次啟動時用 Modelfile 在 `data/ollama` 建立 `pf-qwen3-rag`，並載入 bge-m3。
  4. 啟動模型服務與 `serve.py`，兩者都只綁 127.0.0.1；設定與目前隔離版相同（`PF_AI_FORMAL_INDEX`、`PF_AI_INDEX_AUTO_UPDATE`、向量模型 bge-m3、OCR 模型路徑、雲端關閉）。
  5. 等到健康檢查通過，自動開啟瀏覽器 `http://127.0.0.1:15190`。
  6. 任一步失敗都用中文說明原因與處理方式，並保留 `logs/`。
- `停止專流.bat` 只停這個包啟動的程序（依 `data/pids.json` 並核對程序路徑），不動對方電腦上其他的 Python 或 Ollama。
- 路徑可以有空白與中文；不寫登錄檔、不裝服務、不需要系統管理員權限。

## 安全

- 全部只綁 127.0.0.1，對方網路上的其他電腦連不進來。
- 只含虛構資料；帳號密碼是公開的 `demo-<帳號>`，使用說明會寫明這是展示包，不能放真實資料。
- 雲端供應商維持未設定，任何政策下都不會送出資料。
- 打包腳本最後掃描整個包：不得含 `.env`、`password_hash` 以外的密碼明文、本機絕對路徑、`.git`。

## 實作步驟

1. `serve.py` 與測試：同一個埠提供前端與 `/api`，重新整理任何頁面都回到前端。
2. `build_seed.py`：從空資料庫重建乾淨資料並自我檢查。
3. 啟動、停止、還原腳本，含環境檢查與中文錯誤訊息。
4. `build.py`：取得可攜式 Python、安裝鎖版依賴、複製 Ollama 與模型、build 前端、組成資料夾、掃描、壓縮。
5. 依下面三層驗證，結果記進 PROGRESS；一次獨立唯讀審查。

## 怎麼在乾淨環境驗證

本機是 Windows 11 Home，沒有 Windows 沙箱與 Hyper-V，所以分三層：

**第一層：本機模擬乾淨環境（AI 自動做）**
- 解壓到含空白與中文的新路徑（例如 `C:\Users\Public\專流 展示\`）。
- 啟動時把 PATH 縮到只剩 `C:\Windows\System32`、清掉 `PYTHONPATH`、`OLLAMA_*`、`VIRTUAL_ENV`，確認不會用到本機的 Python、Node、Ollama。
- 啟動期間暫時把 repo 的 `.venv` 與本機 Ollama 安裝路徑加入「不得被讀取」的檢查：掃 `logs/` 與程序清單，包內程序的執行檔路徑都必須在包裡。
- 跑完整展示：登入、15 題自動示範題（D01–D13、D20、D21；改寫 `check_demo_questions.py`，允許指定可攜包的埠）、在瀏覽器手動走 D14–D19（AI 政策與遮罩，沒有自動腳本）、用三份樣板各產生一份文件、停止、再啟動資料還在、還原展示資料後回到乾淨狀態。
- 停止後確認沒有殘留程序、15190／11437 已釋放。

**第二層：CPU 模式（AI 自動做）**
- 強制 Ollama 只用 CPU 再跑一次 D01–D08，記錄每題秒數，寫進使用說明，讓沒有 NVIDIA 顯示卡的人知道要等多久。

**第三層：真正的另一台電腦（需要人類）**
- 由人類在目標電腦（或一台沒裝過開發工具的 Windows）照 `使用說明.txt` 操作，對照一張檢查表：能啟動、自動開瀏覽器、登入、D01／D03／D05／D20 四題、產生一份報價單、停止。
- 失敗時把 `logs/` 資料夾整個傳回來。
- 這一層沒有通過前，不宣稱「可以在別人電腦上跑」。

## 驗收情境

1. 在第一層的乾淨路徑雙擊啟動，3 分鐘內（含第一次建立模型）開出登入頁；之後啟動 1 分鐘內。
2. `yu`／`demo-yu` 登入，專案清單只有展示資料，沒有測試殘留。
3. 15 題自動示範題全部通過（與 15176 隔離版相同基準）；D14–D19 在瀏覽器走一次，結果與示範題目文件相同。
4. 三份樣板可產生文件，編號與報價金額正確。
5. 停止後沒有殘留程序；再啟動資料還在；還原後回到乾淨資料。
6. CPU 模式每題秒數有記錄並寫進使用說明。
7. 包內沒有本機絕對路徑、`.env`、`.git`、gemma4。
8. 人類在另一台電腦完成第三層檢查表。
