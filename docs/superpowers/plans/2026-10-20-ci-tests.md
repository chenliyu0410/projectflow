# CI 與測試環境（ci-tests）

> 分支：`claude/ci-tests-663774`（從 main @3c1294e）。與 api-security、api-correctness、web-fixes 平行；為避免衝突，本工作不改 `docs/PROGRESS.md`、`README.md`，計畫與結果只寫在這份文件。

## 範圍

只改：`.github/**`、`api/tests/conftest.py`、`api/tests/test_migrations.py`、`api/tests/test_health.py`、`api/pyproject.toml`、`api/requirements*`、`web/package.json`、`web/package-lock.json`。不動 `api/app/**`、`web/src/**`。

## 計畫

1. `.github/workflows/ci.yml`：push 到 main 與 pull_request 觸發，三個 job。
   - `api`：Python 3.13、`pip install -r api/requirements.lock`、從 repo 根目錄 `python -m pytest api/tests -q`（SQLite；14 個 PG 測試照常 skip）。
   - `api-postgresql`：PostgreSQL 17 service container；`.github/scripts/run_postgresql_tests.py` 沿用 `deploy/verify.py` 的做法，每個階段建一個全新的專用資料庫（`p2a_migration_*`／`p2b_test_*`），設 `P2A_MIGRATION_TEST_URL` 或 `P2B_TEST_DATABASE_URL`、`DATABASE_URL`、`PF_ACCEPTANCE_MODE=true`、`PF_ATTACHMENT_ROOT`，並以 `no_skip` plugin 把 skip 當失敗。
   - `web`：Node 24、`npm ci`、`npx vitest run`、`npm run build`。
2. `test_migrations.py`：`Config('api/alembic.ini')` 與 `Path("api/...")` 改由 `app` 套件位置推出 api 根目錄，從 repo 根目錄或 `api/` 都能跑。
3. `test_health.py`：補 P0-T1-m1 的三種邊界（查詢結果非 1、查詢階段例外、checker 非布林）。
4. 評估兩個棄用警告，只在測試設定／依賴層級安全時處理。
5. web 依賴升到最新 patch，跑 vitest、build、`npm audit`。

## 結果（2026-10-20）

### Workflow（`.github/workflows/ci.yml`）

| job | 內容 |
|---|---|
| `api` | ubuntu-latest、`actions/setup-python@v7` 3.13（pip 快取以 lock 為 key）、`pip install -r api/requirements.lock`、`python -m pytest api/tests -q` |
| `api-postgresql` | `postgres:17-alpine` service（與 deploy 相同主版本；trust 認證、只綁 runner 本機，repo 不放密碼）、`python .github/scripts/run_postgresql_tests.py` |
| `web` | `actions/setup-node@v7` Node 24（npm 快取）、`npm ci`、`npx vitest run`、`npm run build` |

- `permissions: contents: read`；同一 PR／ref 的舊執行會被取消。
- `run_postgresql_tests.py`：11 個階段（P2a、P2b、P2c、TP-A～TP-G、API races），每階段 `CREATE DATABASE p2a_migration_<uuid>`／`p2b_test_<uuid>`，跑完 `DROP DATABASE ... WITH (FORCE)`。開跑前用 AST 比對 `test_migrations.py` 中名稱含 `postgresql_` 的測試，有漏排就直接失敗，避免新 PG 測試在一般 job 被 skip 而沒人發現。
- `no_skip.py`：pytest plugin，沒收集到測試或有任何 skip 就把 exit code 設為 1（與 `deploy/verify.py` 相同規則）。
- **Playwright E2E 未納入**：需要 `deploy/start.py --acceptance --seed-demo` 起的隔離 Compose 環境（API、Web、PG、gitignored 的 acceptance.env、seed 資料、acceptance marker），33 個 spec 依賴 seed 專案與角色資料。要放進 CI 得在 runner 上建兩個映像、產生私密 env、seed，成本與維護量都高，先維持本機 `deploy/verify.py` 驗收。

- `test_migrations.py`：新增 `API_ROOT`／`ALEMBIC_INI`，由 `app.database` 模組位置推出 api 根目錄（不用測試檔位置，是因為 `deploy/verify.py` 會把測試檔複製到暫存目錄、`api` 指向容器 `/app`，以 app 套件定位兩種配置都成立）。19 處 `Config('api/alembic.ini')` 與 3 處 `Path("api/...")` 全部改用它。
  - RED：舊版從 `api/` 執行 `20 failed, 3 passed, 10 skipped`。GREEN：新版從 `api/` 與 repo 根目錄執行皆 `47 passed, 10 skipped`（含 test_health）。
- `test_health.py`（P0-T1-m1）：新增 11 個案例——查詢結果為 `(0,)`、`(2,)`、`("1",)`、`(1, 1)`、`None` 皆不可用；`connection.execute` 丟 `psycopg.ProgrammingError` 時回 False 且不外洩；checker 回傳 `1`、`"true"`、`"ready"`、`[True]`、`None` 時 `/health/ready` 為 503。
  - 這些是既有行為的回歸測試，所以直接 GREEN。另做突變檢查：把 `main.py` 暫改成 `bool(probe())`、`bool(fetchone())`、只捕捉 `OperationalError`，新案例 9 個失敗；還原後 `git diff api/app/main.py` 為空。

### 棄用警告

| 警告 | 處理 |
|---|---|
| Python 3.12+ sqlite3 預設 datetime adapter | **已處理**。唯一來源是 `check_tp_b_migration_preserves_nodes` 用 raw `text()` 綁定 `datetime`；改以 `bindparam('at', type_=DateTime(timezone=True))` 綁定，和 ORM 寫入方式一致。修正前該測試出現 1 次警告，修正後 0 次；PG 版 TP-B 階段仍通過。 |
| `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2` | **未處理，建議另案**。Starlette 1.7 的 TestClient 優先載入 `httpx2`，找不到才退回 `httpx` 並警告。要消除就得新增 `httpx2`（會帶入 `httpcore2`、`truststore`），而 2.15.1 在 2026-10-19 才發布、太新；`api/app/ai/model.py` 與 `test_ai.py` 仍用 `httpx`，等於同時存在兩套 HTTP client。這屬於依賴選型決策，不只是在測試設定調整。建議：另開工作評估把 `httpx` 換成 `httpx2`（app 與測試一起換），或在 requirements 只把 `httpx2` 列為測試依賴，並等版本穩定至少兩週後再鎖版。目前也不在 pytest 設定裡隱藏這個警告，讓它持續可見。 |
| （另發現）Alembic `No path_separator found in configuration` | 範圍外。需要在 `api/alembic.ini` 加 `path_separator = os`，這個檔案不在本分支允許清單內，留作後續。 |

### 已知限制與後續

- PG 的 API races 階段在 **Windows 主機**會失敗：`attachment_store.runtime_lock` 在 Windows 用排他的 `msvcrt.locking`，多個 TestClient 同時持有就 `PermissionError`；Linux 用共享 `fcntl.flock`，所以 CI 與容器內都正常。這是 `api/app` 的平台差異，不在本分支範圍。
- `src/tree.test.tsx` 的「promotes a task and undoes it with Ctrl+Z, once」在主機高負載（同時跑 API 全量）時連續兩次失敗，單獨跑檔案或負載低時通過，判斷是 `findByText` 預設 1 秒逾時造成的時序 flake。GitHub runner 也可能遇到，屬 `web/src/**`，留給 web 相關工作處理。
- `test_collaboration_postgresql.py` 仍寫死 `Config('api/alembic.ini')`，從 `api/` 執行會失敗；不在本分支允許清單內。CI 從 repo 根目錄跑，不受影響。
- **要 push 後才能在 GitHub 確認**：Actions 是否正常觸發（push main／PR）；`actions/*@v7` 在 GitHub 託管 runner 上的實際行為；service container 健康檢查與 `127.0.0.1:5432` 連線；pip／npm 快取命中；整體執行時間（本機 API 全量約 14～17 分鐘）。
