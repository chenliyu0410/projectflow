# COPILOT-SIMPLIFY：AI 助手只留對話與分類快捷題（短規格與計畫）

依人類 2026-10-28：「我要改AI助手的介面，使用者只要能清楚看到自己問題跟AI回答就好，然後有固定快捷鍵可以當問題」「現在有太多要設定，可以簡化一點」「盡量讓畫面簡潔，留下必要的就好」。看過現況／方案 A／方案 B 對照圖後選方案 B，並同意拿掉下列選單（含專案選單）：「可以改」。依 WORKFLOW §14（精簡流程）。

## 展示目標

打開 AI 助手，畫面只有：標題列（「AI 助手」、⚙、關閉）、一排分類標籤、對話區、固定快捷題、輸入框。點快捷題或自己打字就能問，不需要先選任何設定。問題靠右、回答靠左，回答下方只留收合的「來源 N 份」與「資料處理紀錄」。

## 版面

| 區塊 | 內容 |
|---|---|
| 標題列 | 「AI 助手」、⚙（展開／收合進階區）、✕ |
| 分類標籤 | 只顯示目前公司有資料、使用者有權限的分類（見下表）；點選即切換，清空對話 |
| 對話區 | 沿用現有問題／回答卡、來源、資料處理紀錄、SQL 表格、原文與預覽區 |
| 快捷題 | 目前分類的固定題目，永遠在輸入框上方（不論有無對話） |
| 輸入列 | 輸入框＋送出；自己打字時照目前分類查 |
| ⚙ 進階區（預設收合） | 模型狀態一行、預覽提供給模型的資料、正式文件的索引更新與狀態、本地模型連線設定（`can_configure`，維持只限本機管理者） |

## 分類與快捷題

題目沿用 `copilotScenarios.ts` 現有示範題，每題可自帶 `history`、`mode`、`project`（專案以標題開頭比對），使用者不用另外勾選。

| 分類 | 資料／查詢方式 | 顯示條件 | 快捷題 |
|---|---|---|---|
| 文件問答 | dataset-v1・rag | 一律 | 現行交付需要幾張截圖？／風險原因與處理方式／採購追蹤紀錄 |
| 資料分析 | dataset-v1・sql | `can_sql` | 各部門逾期未完成數／請問有哪些專案超支？／各專案加權不良率／本週到期未完成任務／供應商已收貨延遲率 |
| 新人報到 | starter-v1・rag | 毛研食品 | 新人課程目前什麼時候、在哪裡上？／只有2位新人，為什麼做20份歡迎包？／給新同事用的電腦弄好了沒？／新人課程原本哪天？為什麼改期？（含歷史）／列出全部未完成工單（work_orders） |
| 正式文件 | formal-v1・rag | 毛研食品且 `formal_available` | 新人報到地點在哪一樓？（增量索引展示）／新人報到地點原本和現在分別在哪一樓？（含歷史）／設備申請流程怎麼做？（隔離索引展示）／新人報到要先去哪裡換證？（OCR 示範） |

預設選第一個分類（文件問答）。自己打字：用分類的資料集與查詢方式，專案為全部可見、不含歷史；資料分析沿用「依輸入問題辨識」與「確認執行」建議按鈕。

## 拿掉

示範情境、AI資料集、查詢方式、AI展示專案／查詢專案、分析種類這 5 個選單；「包含歷史版本」勾選；標題列的設定摘要按鈕；上方兩行狀態說明與資料區說明段落；兩張示範步驟卡（換帳號看權限、AI 政策與遮罩，內容仍在 `docs/ai-demo-questions.md`）。查詢範圍一律為目前公司全部可見專案（快捷題自帶專案者除外）。

## 不變

API、權限、資料、模型路由、雲端關閉、來源與原文開啟、SQL 表格、預覽內容、401 回登入、取消查詢與請求中止。無資料時仍顯示「資料尚未就緒」錯誤狀態，快捷題停用。

## 步驟

1. 開 `feature/copilot-simplify`。
2. 先改／新增 Vitest：預設只見分類標籤與快捷題、無 5 個選單；切分類換快捷題與資料集；一般成員看不到「資料分析」；快捷題自帶歷史／工單／專案時送出正確 payload；⚙ 收合模型設定與預覽。RED 後實作到 GREEN。
3. 改 `CopilotPanel.tsx`、`copilotScenarios.ts`、`styles.css`。
4. 更新引用舊選單的 E2E 輔助與規格；可在本機執行的跑一次。
5. Vitest 全量、`npm run build`；15173 部署 web 後 1280／375 實測文件問答、資料分析、新人報到各一題。
6. 一次獨立唯讀審查，修正後複核；更新 PROGRESS，`--ff-only` 合併回 main（D2）。
