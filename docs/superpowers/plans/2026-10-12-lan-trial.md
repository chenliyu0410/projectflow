# LAN-TRIAL：本機15173開放同網域試用（短規格／計畫）

> 精簡流程（WORKFLOW §14／§14.1）。人類2026-10-12指示：「你先弄一個我本機能跑的，我要給同網域的其他人測試」。這是 §14 第7點要求的LAN人類授權，只限本機試用入口。

## 目標

同一個網路的其他電腦，用瀏覽器開 `http://<這台電腦的IP>:15173` 就能登入試用。這台電腦自己照舊用 `http://127.0.0.1:15173`。

## 範圍

- `deploy/start.py` 新增 `--lan`：web 綁定所有網卡（`0.0.0.0`）。不加 `--lan` 時一律綁 `127.0.0.1`，而且由 start.py 明確指定，不沿用 shell 或 `.env` 裡殘留的設定。
- `deploy/docker-compose.yml` 的 web 埠改成 `${WEB_BIND:-127.0.0.1}:${WEB_PORT:-15173}:80`。API 埠維持只綁 `127.0.0.1`，DB 不對外。其他人只經過 web 的 nginx 代理 `/api`。
- `--lan` 不可和 `--acceptance` 同時使用，驗收環境永遠只綁 loopback。
- 啟動成功後印出區網網址提示。就緒檢查照舊打 `127.0.0.1`。
- 文件：`docs/formal-development.md` 補「同網域試用」段落（啟動命令、防火牆由人類設定、帳號與風險）。

## 延後／不做

- HTTPS、正式帳號管理與改密碼、反向代理強化、商業／雲端部署。
- Windows 防火牆與網路類型：屬於系統安全設定，由人類自行處理，AI 只提供命令。

## 權限與安全

- 不改 API 權限。登入 cookie 是 HttpOnly、SameSite=Lax，沒有 Secure 旗標，HTTP 區網可用。
- 左下展示公司切換和 AI 模型設定，照舊只在 Host 是 `127.0.0.1`／`localhost` 時開放。區網的人看不到這兩個入口。Host 標頭可由用戶端偽造，但這兩個功能本來就要管理員帳號，只限信任的網路使用。
- 資料包還原後所有帳號密碼都是 `demo-<帳號>`，而且寫在 repo 裡。同網路的任何人都能用管理員登入；只在信任的網路開放，試用完不加 `--lan` 重啟即關閉。

## 資料變更

無 migration、不 seed。web 容器會因埠設定改變而重建；API／DB 容器設定不變，資料 volume 保留。

## 允許修改的檔案

`deploy/docker-compose.yml`、`deploy/start.py`、`api/tests/test_deployment.py`、`docs/formal-development.md`、`docs/PROGRESS.md`、`README.md`（必要時補一句）。

Plan fix（審查後補列）：`web/src/api.ts`、`web/src/components/InventoryPanel.tsx`、`web/src/components/WorkflowLibrary.tsx`、新測試 `web/src/new-id.test.tsx`。原因：區網用 `http://<IP>` 開啟不是安全情境，瀏覽器不提供 `crypto.randomUUID()`，庫存入帳／退貨／沖銷和模板新增節點會丟錯。改用共用的 `newId()`：有 `randomUUID` 就用，沒有就用 `crypto.getRandomValues` 組 UUID v4。

## 步驟

1. 先在 `api/tests/test_deployment.py` 寫測試並跑出 RED：
   - `--lan` 時每個 compose 命令的環境 `WEB_BIND=0.0.0.0`，接受 `0.0.0.0:<埠>`，就緒檢查仍打 `http://127.0.0.1:<埠>`。
   - 預設啟動即使繼承 `WEB_BIND=0.0.0.0`，也強制 `127.0.0.1`；`0.0.0.0` 回報仍拒絕。
   - `--lan` 搭配 `--acceptance` 在執行任何命令前拒絕。
   - compose 契約：web 埠用 `WEB_BIND` 且預設 `127.0.0.1`，API 埠仍固定 `127.0.0.1:`。
2. 實作到 GREEN，跑完整 `test_deployment.py` 與 `docker compose config`。
   - 前端：`newId()` 在沒有 `randomUUID` 時仍產生合法 UUID v4；`web/src` 產品程式不得再直接呼叫 `crypto.randomUUID`。跑相關 Vitest 與 build，web 映像需重建。
3. 一次唯讀獨立審查。
4. ff-only 合併 main，依 D50 push。
5. `python deploy/start.py --lan` 重啟 15173（不 seed），核對 API／DB 容器未重建、health ready、從區網 IP 打開登入頁。

## 驗收情境

- 本機 `http://127.0.0.1:15173` 和 `http://<區網IP>:15173` 都回登入頁，`/api/health/ready` 為 ready。
- 區網 IP 回的是同一個 web bundle；登入照舊在 `127.0.0.1` 驗證，區網登入由人類或試用者確認。
- `docker compose port api 8000` 仍是 `127.0.0.1:18000`。
- 不加 `--lan` 重啟後，web 回到只綁 `127.0.0.1`。
- 其他電腦實際連線由人類設定防火牆後自行確認，AI 無法從本機代測。
