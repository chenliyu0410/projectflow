# UI4 專案工作區與操作對齊 — 精簡規格／計畫

2026-10-09，依D69／D70與D65精簡流程。範圍是專案節點頁（標題列、階段條、分頁、看板、回報卡、紀錄、成員）、時程、相依圖、模板庫與審核中心的畫面與操作位置。UI4只接既有功能與既有資料；需要新API、新欄位或新寫入規則的操作歸TP-A至TP-G。本文件是實作範圍，不表示畫面已改版或驗收通過。

## 對照依據

Demo在另開的127.0.0.1:18005用Playwright全新context截圖（毛研食品、力瑜／專案負責人）；正式版在隔離環境`projectflow-ui3cmp`（15179，acceptance marker；seed＋三個展示腳本）以yu登入截圖。兩邊都取專案層看板、階段層看板、子任務紀錄、專案時程、專案相依圖、成員分頁（Demo）、模板庫、審核中心，寬度1280／1440／375。截圖、量測JSON與腳本在ignored `.superpowers/ui4/baseline/`。

量測重點：主區寬度兩邊相同（1280為678、1440為838）。Demo看板4欄（1280每欄148），正式版是5欄加左側180px節點樹，每欄只剩99、卡片79px寬、標題被擠成兩字一行。Demo節點頁的資訊都在標題列；正式版把同樣資訊放在節點詳情卡，並在每一層重複列出所有待核准閘門。

## 範圍與決定

- **節點頁結構**（照Demo由上而下）：麵包屑 → h1目前節點（專案層是專案名）→ meta列 → 右側操作 → 子任務的回報卡 → 專案層階段條／階段層閘門列 → 分頁列 → 內容。h1與meta放在`aria-label="節點詳情"`區塊，保留既有測試錨點。
- **meta列**：任務顯示「負責：名字・部門」，階段顯示「負責人」，專案不顯示；接著「期間：開始 – 截止」（上層節點取自己與可見後代的最早開始／最晚截止，沒有日期顯示「未設定」）、完成率進度條與%、狀態標籤、等待前置標籤。完成率沿用總覽的規則：完成任務數 ÷（可見任務數 − 已略過），沒有任務顯示「—」；Demo的加權進度歸TP-A（AI代決，可推翻）。階段仍標註「階段狀態為手動設定，不代表子任務完成率」。
- **操作**：負責人頭像；可改狀態時顯示精簡「狀態」下拉（拖曳改狀態歸TP-A，下拉是目前唯一入口）；「編輯節點」「新增子節點」沿用既有表單與權限；「另存為模板」「套用模板」照位置顯示但停用並標「尚未提供」（TP-E）。
- **階段條**：專案有頂層階段時顯示。每段：完成率條、%、閘門狀態（已核准、目前階段、未過、沒有閘門）。目前階段＝第一個非完成／略過的頂層階段（與總覽相同）。點擊進入階段。
- **閘門列**：階段有閘門時顯示「階段閘門」、狀態，待核准且有權限時顯示「核准閘門」。專案層與任務層不再列出全部閘門；審核中心仍可核准。
- **分頁**：看板・時程・相依圖・文件・資料・成員與權限・紀錄；子任務（沒有可見子節點的任務）把紀錄放第一並預設打開；回到上層時從紀錄改回看板。「文件」「資料」停用並標「尚未提供」（UI5／F1）。「時程」「相依圖」在任何一層都顯示整個專案，非專案層加一行說明；節點自己的時程與相依圖歸TP-A（AI代決，可推翻）。專案層「成員與權限」說明專案層頁面排在TP-F。
- **移除主區節點樹**（AI代決，可推翻）：Demo沒有；往下靠看板卡片與階段條，往上靠麵包屑，整棵樹的階層在時程分頁。看不到上層的可見節點（孤兒）與損壞的循環資料，照原本`visibleRoots`規則放到專案層看板，仍可點選。
- **看板**：4欄「待處理／進行中／待確認／完成」，完成欄含已略過（卡片標「已略過」）。狀態名稱維持正式版既有用詞（與Demo「待辦／審核中／已完成」只差文字，全站一致；可推翻）。專案層有階段時，卡片是各頂層階段底下的子節點，加階段標籤；其他層是下一層子節點。卡片：標籤（階段、類型、延遲、🔒等待前置、已略過）、標題、腳註（頭像、負責人・部門、期間），可改時加精簡狀態下拉。1280／1440為4欄；860以下每欄240px，在看板內橫捲。子任務數、迷你進度、展開、等待名稱、✓回報快捷歸TP-A。
- **回報卡**：子任務頁在標題下。依狀態顯示：完成回報（需填說明＋「回報完成」）、v N 等待確認（摘要＋送出者；有權限時審核意見與「確認回報」「退回回報」）、已退回（意見＋「重新回報」）、已完成（摘要＋確認者）、已略過。按「回報完成」或「重新回報」才展開既有表單，有「取消」；略過／重新開啟／恢復維持在卡片內。送出、自行確認、審核規則不變。
- **紀錄**：標題加數量（已全部載入時寫N，還有下一頁時寫「已載入N」），樣式照Demo；協作編輯移到成員與權限。
- **成員與權限**：「此節點的成員」（負責人、部門，以及既有協作人員與部門編輯）；「你（名字・角色）在此節點可以」依節點capabilities列✓/✗（檢視、編輯節點、指派負責人、新增子節點、寫筆記與附件、送出完成回報、確認回報、管理協作、略過與恢復）。角色權限表與部門管理歸TP-F。
- **時程**：工具列「總覽圖」標籤＋說明＋日／週／月分段鈕（取代下拉）；標籤欄270px（860以下150px）：展開鈕、狀態點、名稱、✎改期（保留「調整日期：名稱」）；列高約36px；任務條用專案色、上層節點外框條、已完成灰色；月份＋日／週兩層刻度；今天線與日期。手機也顯示同一張圖並在框內橫捲，移除另一套手機卡片（改期用✎）。「未排程」清單保留。自動順延、關鍵路徑、復原、部門篩選、拖出新增歸TP-C，不放按鈕。
- **相依圖**：工具列「＋建立相依連線」（有權限才有）切換既有新增表單；圖在前：任務方塊200×58（狀態點、期間、上層路徑、標題、🔒），由左到右依前置層級排列；直角箭頭，前置已完成或略過為灰實線，未完成為橘虛線；說明文字。既有連線清單與移除按鈕收進「連線清單（N）」。拖線建立歸TP-D。
- **模板庫**：保留公司模板／產業範本分頁。公司模板區標題列「工作流模板」＋「新增模板」；卡片：「公司模板」標籤、含相對日期標籤、名稱、統計、可展開的預覽階段、「查看與編輯」（既有詳情、編輯、複製）與主按鈕「用這套工作流建立專案」（可建立專案的角色才有；打開側欄同一張建立表單並預選模板）。下方「任務模板」區說明尚未提供（TP-E）。
- **審核中心**：「待確認的完成回報（N）」卡片清單；「待審核的跳過申請」說明尚未提供（TP-F）；「待核准的階段閘門（N）」改表格（專案／階段、送出時間、核准閘門）。審核規則與既有分頁載入不變。

## 權限

沒有新增API或寫入。所有按鈕沿用既有capabilities與角色判斷；完成率、期間、延遲、階段條都只從目前使用者看得到的節點計算。唯讀與成員看到的按鈕與現在相同。停用的「尚未提供」按鈕不送任何請求。

## 驗收情境

1. 1280／1440：專案層看板4欄、每欄寬度接近Demo（148／188），卡片標題不會一字一行；階段條、分頁、標題列位置與Demo相同。
2. 從專案層卡片進入任務、從階段條進入階段、從麵包屑回上層；子任務打開時預設在紀錄，回報卡收合；按「回報完成」送出、管理者確認或退回，Gate與FS前置照舊阻擋與解鎖。
3. 時程可切日週月、點名稱進入節點、✎改期儲存；相依圖新增與移除連線、點方塊進入任務。
4. 模板庫從卡片「用這套工作流建立專案」完成建立；審核中心核准閘門與確認回報。
5. 成員帳號與唯讀帳號：看不到的節點不出現在看板、階段條、完成率與相依圖；唯讀沒有狀態下拉與寫入按鈕。
6. 375：選單與副手抽屜照舊；看板、階段條、時程在框內橫捲，頁面沒有水平捲動；空、載入、錯誤重試、登入失效仍可操作。
