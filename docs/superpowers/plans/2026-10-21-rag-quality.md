# RAG-QUALITY：五項問答品質修正

依人類 2026-10-21 指示與 WORKFLOW §14 執行。沿用 feature/review-fixes；單一寫入者。既有 SYS-PACK4 看板草稿及使用者解壓資料夾保持原樣。

## 目標與原因

修正 Q04 引用未支持品保姓名、Q05/Q07 正確答案後又否定證據、Q10 里程碑日期錯配、Q13 合計錯誤。CSV 現在將表頭與資料分開；生成器只驗引用 ID，未保留欄位與原文對應。

## 範圍與介面

- CSV 每列帶欄名；空白／重複／缺少表頭仍保留位置及所有值。
- 給模型來源標題、版本，要求短答並選取系統編列的證據 ID；後端將 ID 映射回原始整行／CSV 整列，再檢查原文並產生引用。模型不負責抄寫引用，證據最多 96 個（超過時回退完整來源段落）。虛構資料在題目指定的展示範圍內仍可回答。
- 計算由模型選擇伺服器預先綁定來源／數值的 number_id 與四則操作，後端驗證原文、數字並以 Decimal 計算；不執行模型程式或自由運算式，不硬編題庫答案。無法驗證時沿用原文降級。
- 不改 DB schema、角色 ACL、業務資料與前端。索引 pipeline 升版後重建衍生索引，保留舊 chunk 供原問答引用。
- 固定原始 20 題與基線報告；先同模型比較，若小模型未達標則以本機已安裝模型實測選用，明記模型差異；新報告另存，包含檢索原文供獨立複核。Q18 舊判分詞彙漏收「並無」的誤判獨立註明。

## 步驟及驗收

1. 補 CSV、引用原文、算術的失敗測試與不同數值變體；實作後跑相關 RAG／文件權限回歸。
2. 隔離 SQLite 跑同一 20 題真實 bge-m3／實測選定的生成模型；每題查答案、引用、當前版本、拒答、矛盾與算術。一次獨立唯讀審查。
3. 本機更新前 pg_dump／檔案 tar 備份、業務資料及附件逐值 SHA；只重建 API，重索引衍生資料，不 seed／restore。資料及原附件前後一致，舊問答來源仍可讀。
4. 健康檢查與本機問答冒煙，開啟試用；記錄真實結果與限制，明確路徑提交，未授權 push／merge 不執行。

## 實驗修正紀錄

逐字引用 schema 對 3B 模型造成機械複製失敗，改為伺服器證據 ID；數字與來源分開選仍會錯配，改綁定 number_id。所有中間結果保留，不以較寬鬆驗證掩蓋。7B 比較時日誌明確出現 5006→2050 tokens 截斷，該輪無效；改明確 num_ctx=16384、精簡數字目錄、問題置後，重新比較。未改題目／標準答案，不以一般資料不足或原文降級冒充通過。
