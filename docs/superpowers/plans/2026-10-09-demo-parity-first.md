# Demo 畫面與操作優先路線（D69）

2026-10-09人類要求「先以做到與DEMO相同畫面、功能為優先進行，功能可以慢慢補，重新規劃」。本次交付規劃，未修改產品或15173。本文件取代舊的「UI1之後直接P2d」順序；P2a/b/c及UI1/2已完成成果保留。

## 交付原則

以`projectflow-full-demo.html`實際畫面、頁面結構與操作路徑作為基準。先讓使用者看見與操作到同樣的產品，再逐步補齊缺少的持久化與進階規則。不是另設計一套近似風格，也不以更多展示資料替代介面對齊。

每個畫面分兩項追蹤：**畫面／互動對齊**與**正式功能完成**。前者可以先交付，不能因此將後者勾為完成。既有真功能保持可用；缺少後端的操作可在明確標示的「展示預覽」中使用隔離示例，不能混入正式資料或顯示假的儲存／AI／ERP成功訊息。尚無預覽的動作說明目前限制，不設可點卻無反應的按鈕。

15個現有展示專案與五公司繼續使用，保留人類調整與回報；不重設資料、不改Demo。不直接複製Demo角色切換／重設資料的權限捷徑；正式登入、公司隔離及API授權維持。相同功能指產品體驗，不要求複製安全缺口。

## 每階段驗收方式

1. 先在隔離環境取得Demo與正式版同尺寸、同頁面、相近資料量的對照圖，列出可見差距；不清人類Demo儲存。保留1280、1440、375視圖，長名稱與空／錯誤狀態也能操作。
2. 建立逐頁表：Demo位置／動作、正式版位置／動作、畫面差距、資料來源（正式／展示預覽）、缺少功能、歸屬階段。每批交付更新兩個完成欄位，禁止只靠測試通過宣稱畫面相同。
3. 檢查布局、欄寬、密度、字級、間距、顏色、分頁順序、捲動區與操作位置；不是只比配色。桌面不強制手機式縱向堆疊；手機可適配但不遺失核心操作。
4. 沿D65一位独立審查、一次相關完整回歸；後續只重驗受影響部分。真业务寫入測試在隔離環境，既有功能／角色／公司隔離不退步。
5. 交付附對照圖、已接真功能／仍展示預覽清單與操作入口；保留DB/files/env，依D50發布15173與push。人類視覺與操作簽核不代勾。
