# F1-RET 採購退貨、工單退料與沖銷

使用者2026-10-12指示「開始做退貨退料與沖銷」，為同提案第3次交付。延續F1-PO／F1-WO的庫存流水：實物退回與錯帳更正都以新的反向流水記錄並連回原紀錄，原流水不修改、不刪除。使用者同日選定：退貨恢復未收（等待補貨）；已結案單據須先重新開啟才能退貨、退料或沖銷。

**範圍**
- 採購退貨：採購紀錄新增「採購退貨」，扣庫存。有明細的單只能退明細內物料，單位須一致，數量不超過該列已收；退貨扣回已收、未收恢復，狀態可由已收齊回到部分收貨；不補貨時調低訂購數量或結案。明細顯示累計已退。無明細的舊單可自由退，但不超過該單該物料未計入明細的淨收貨。
- 工單退料：工單新增「退料回庫存」，加回庫存，只能退本工單淨領料大於零的物料，不超過淨領料；累計領料改為扣除退料與沖銷後的淨額。
- 沖銷：收貨、退貨、領料、退料、完工、人工調整都可沖銷一次，產生數量相同、方向相反的沖銷流水並連回原紀錄；原紀錄標示「已沖銷」。沖銷紀錄不可再沖銷，需要時重新入帳。沖銷同步回復明細已收、計畫已完工、淨領料與庫存；結果超出範圍（庫存不足、已收小於零或超過訂購、淨領料小於零）時拒絕並說明。
- 結案：已結案採購單或工單拒絕退貨、退料與沖銷，與收貨、領料、完工一致，須先填原因重新開啟。
- 重送：退貨、退料、沖銷都帶操作識別碼；同一識別碼重送回傳原流水，不同內容重用拒絕；同一筆的兩個併發沖銷只成功一個。

**權限與一致性**：與F1-INV／F1-PO／F1-WO相同，限管理者／專案負責人；一般角色維持唯讀、看不到庫存。API每次強制公司與可見性，沖銷時原流水的物料與單據也須可見。所有寫入先鎖公司列，再鎖單據、明細或計畫，與既有入帳同鎖序；稽核記錄`inventory.return`、`inventory.issue_return`、`inventory.reversal`。

**延後**：退貨單號／供應商退貨單據、退貨原因代碼、折讓與金額、退貨後自動建立補貨或品質任務、部分沖銷、沖銷的再沖銷、會計期間鎖帳、批號、一般角色查看。

**資料**：migration 0019在`inventory_movements`新增nullable `reversal_of`（同公司複合FK指向原流水，唯一，每筆最多沖銷一次）。新增三種流水：`return`（採購、負數、可帶明細）、`issue_return`（工單、正數）、`reversal`（必有`reversal_of`，沿用原流水的採購／工單／明細與計入計畫標記）；重建種類、明細與計畫CHECK以容納新種類。舊流水全保留、不seed、不回推；已有新種類流水時拒絕降級。明細只要有任何流水引用就不可刪除或更換物料／單位（避免退貨歸零後刪除仍被引用的明細）。

**步驟**：(1) migration、模型與測試；(2) 退貨／退料入帳與上限檢查；(3) 沖銷端點與流水標示；(4) 採購／工單明細顯示已退、淨領料；(5) 前端退貨、退料模式與流水沖銷；(6) Vitest、E2E；(7) 一次獨立審查、相關回歸、文件與部署。

**驗收**：採購兩列明細收齊→部分退貨（已收齊→部分收貨、未收恢復、顯示已退）→補貨再收齊→超退、非明細物料、單位不符拒絕→沖銷錯收（庫存與已收回復）→沖銷退貨→重複沖銷與沖銷沖銷紀錄拒絕→結案後退貨與沖銷拒絕→重開可做。工單領料→退料（淨領料減少）→超退、未領物料拒絕→沖銷計入計畫的完工（已完工減少、狀態回生產中）→沖銷領料（淨領料不得小於零）。人工調整可沖銷；庫存已被領用時沖銷收貨拒絕。同UUID重送只入帳一次；真PG併發退貨不超退、併發沖銷同一筆只成功一次；跨公司／一般角色拒絕；migration保留舊流水並拒絕有損降級；既有無明細、無計畫流程不變。相關API、全前端Vitest、build、1280／375 E2E（隔離15175）；依WORKFLOW §14一次獨立唯讀審查。備份正式DB／files後部署15173並核對原資料保留；依D50 ff-only合併與push。
