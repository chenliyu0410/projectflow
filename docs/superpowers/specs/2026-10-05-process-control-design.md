# 工作流架構（精簡版）設計

- 日期：2026-10-05
- 範圍：`projectflow-full-demo.html`、`tests/`
- 前置：W2 部門模型已完成，`db.v = 4`
- 來源：D31、D41、D42，以及 `docs/reference/2026-10-05-w3-current-flow-sources.md`
- 狀態：草案，需人類看一次後定稿

## 1. 問題

目前 Demo 已有模板庫、階段閘門、前置條件、任務狀態和部門模型，但這些能力還不是一個完整的「工作流架構」：

- 模板庫偏向保存任務樹，沒有把「工作流」作為使用者可管理的對象。
- 使用者不能清楚地從畫面建立一套新工作流，再用它產生專案。
- 階段、任務、負責部門、前置條件和關卡分散在不同操作裡，展示時不容易說明「公司可以自己把流程放進來」。
- 關卡目前存在，但還沒有明確做到「上一階段關卡沒過，後續階段不能開始」。

D42 已決定：W3 不以內建某一套筆電、行銷或連接器流程為核心，而是先完成可自行新增、編輯、套用工作流的功能架構。個別工作流內容之後由使用者自行添加。

## 2. 目標

1. 工作流模板可以由使用者在 Demo 裡建立、編輯、複製、刪除。
2. 一套工作流模板包含階段、任務、負責部門、協作部門、前置條件和階段關卡。
3. 使用者可以從工作流模板建立新專案，系統產生專案、階段、任務、前置條件和關卡。
4. 階段關卡未核准時，後續階段的任務不能開始或完成；核准後解鎖。
5. Demo 保留少量內建範例，讓畫面一打開就能展示，但功能重心是可自行新增工作流。

不在本次範圍：

- 不做正式版的低程式碼流程設計器。
- 不做拖拉式流程圖編輯器。
- 不做匯入 Excel 的功能；D41 的 Excel 只作內建範例和測試素材。
- 不新增或維護人員帳號。
- 不新增 W2 以外的部門管理能力。
- 不做範本指定關卡核准人、總經理角色、強制通過關卡、略過整個階段、完成報告必附交付物。
- 不處理外部 ODM 的帳號或外部協作權限。

## 3. 資料結構

### 3.1 資料版本

W3 需要讓工作流模板可編輯，現有 `db.templates[]` 雖已能保存任務樹和前置條件，但缺少工作流編輯需要的關卡資料與流程類型標記。因此 W3 將資料升到 `db.v = 5`。

`load()` 需接受 v2、v3、v4、v5，並依序升級；`save()` 寫 v5。

### 3.2 工作流模板 `db.workflows[]`

新增 `db.workflows`，每筆是一套可建立專案的工作流：

```js
{
  id: 'wf-laptop',
  name: '筆電新機種專流',
  desc: '從市場洞察到售後與停產的產品開發流程',
  category: '新產品',
  version: 1,
  builtin: true,
  stages: [
    {
      id: 's1',
      title: '市場洞察',
      dept: 'd-adm',
      gate: { title: '立案審查（G0）', criteria: 'Business Case 與目標成本完成' },
      tasks: [
        { id: 't1', title: '市場與競品分析', dept: 'd-adm', depts: [], dur: 5 },
        { id: 't2', title: '晶片平台 Roadmap 對齊', dept: 'd-rd', depts: [], dur: 5 }
      ]
    }
  ],
  deps: [
    { from: 't1', to: 't2', type: 'FS', lag: 0, enf: 'hard' }
  ]
}
```

規則：

- `stage.id`、`task.id` 是模板內部 id，不等於實際節點 id。
- `dept` 必須是 `db.departments` 的 id。
- `depts[]` 是協作部門 id。
- `gate` 可為 `null`；有 gate 的階段建立專案時會寫入 `db.gates[phaseId]`。
- `deps[]` 只能參照同一 workflow 內的 task id。
- `builtin: true` 的模板可以複製，但不能刪除；可以另存為新的自訂模板。

### 3.3 v4 → v5 升級

1. 加上 `db.workflows = []`。
2. 依 D41 的來源建立兩套內建工作流：
   - 「筆電新機種專流」：主要範例，含階段關卡 G0-G6。
   - 「實體活動專流」：輔助範例，沒有 gate 或只放簡單核准節點。
3. 保留既有 `db.templates[]`，不刪除舊模板，避免破壞 W2 已完成的模板行為。
4. `db.v = 5`。

### 3.4 種子資料

`seed()` 直接產生 v5：

- 預設包含 `db.workflows` 的兩套內建工作流。
- Demo 中保留既有寵物食品專案，另外新增一個由「筆電新機種專流」產生的示範專案。
- 筆電示範專案前兩個階段已完成或接近完成，第三階段是目前階段，後續階段會被第三階段 gate 擋住。

## 4. 工作流管理

### 4.1 入口

沿用現有「模板庫」頁，不新增主導覽項目。頁面分成兩塊：

1. 「工作流模板」：顯示 `db.workflows`。
2. 「任務模板」：保留既有 `db.templates`。

這樣 W3 不破壞舊模板能力，也讓展示時一眼看出「工作流」是更高層的流程模板。

### 4.2 工作流列表

每張工作流卡片顯示：

- 名稱、分類、說明。
- 階段數、任務數、關卡數、前置條件數。
- 主要動作：
  - 建立專案
  - 編輯
  - 複製
  - 刪除（內建模板 disabled）

所有介面文字使用繁體中文。

### 4.3 工作流編輯

Demo 階段採用表單式編輯，不做拖拉式設計器。

編輯對話框內容：

- 基本資料：名稱、分類、說明。
- 階段清單：
  - 新增階段、刪除階段、上移、下移。
  - 階段名稱、預設負責部門。
  - 關卡：可開啟/關閉；可填關卡名稱與完成標準。
- 任務清單：
  - 每個階段可新增、刪除、上移、下移任務。
  - 任務名稱、負責部門、協作部門、工期天數。
- 前置條件：
  - 精簡版只支援任務之間的 FS hard 前置。
  - 使用兩個下拉選單選「前置任務 → 後續任務」。
  - 系統阻擋循環相依。

編輯儲存規則：

- 名稱必填。
- 至少 1 個階段。
- 每個階段至少 1 個任務。
- 工期天數至少 1。
- 部門 id 必須存在。
- 前置條件的 from/to 必須存在且不可相同。
- 儲存走 `commit(label, fn)`，並用 `log(null, '工作流', text)` 記錄。

### 4.4 複製與刪除

- 複製：建立新 id，名稱預設為「{原名} 副本」，`builtin: false`。
- 刪除：只允許刪除自訂工作流；內建工作流顯示 disabled 與提示。

## 5. 從工作流建立專案

### 5.1 建立專案對話框

在工作流卡片按「建立專案」後，開啟對話框：

- 專案名稱，預設「{工作流名稱}專案」。
- 開始日期，預設今天。
- 專案負責人，沿用既有使用者清單，預設目前使用者。

送出後：

1. 建立 project 節點。
2. 依 workflow stages 建立 phase 節點。
3. 依 workflow tasks 建立 task 節點。
4. 依 workflow deps 建立 `db.deps`。
5. 依 stage gate 建立 `db.gates[phaseId]`，狀態預設 pending。
6. 依工期和前置順序排出初始 start/end。

### 5.2 權限

- 建立、編輯、刪除工作流：沿用 `can('templates')`，也就是目前系統管理員。
- 從工作流建立專案：系統管理員與專案負責人可用。
- 其他角色只可檢視工作流列表。

## 6. 關卡阻擋規則

### 6.1 被擋範圍

對同一專案內的階段，若某階段 `A` 的 `db.gates[A.id].status` 不是 `approved` 或 `overridden`，則：

- `A` 後面所有階段的任務不能從 todo 切到 doing。
- `A` 後面所有階段的任務不能直接切到 done。
- 後續階段的階段節點本身仍可瀏覽與規劃。

當有多個未過關卡時，提示顯示最前面那個未過關卡。

### 6.2 不被擋的操作

- 可瀏覽後續階段與任務。
- 可編輯後續階段任務的基本資料、負責部門、負責人與時程，只要原本權限允許。
- 可新增筆記、文件和前置條件，只要原本權限允許。
- 可核准目前階段的關卡。

### 6.3 提示文字

任務被擋時，沿用既有前置阻擋體驗，顯示：

`階段關卡未通過：{階段名稱}／{關卡條件}`

看板卡片與任務頁可沿用現有「等待前置」標籤。需要時標籤 title 裡列出關卡原因。

## 8. 測試

在 `tests/records.test.js` 新增瀏覽器測試：

1. v4 資料升級到 v5 後會新增 `db.workflows`，既有 `db.templates` 保留。
2. 種子資料有兩套內建工作流：「筆電新機種專流」、「實體活動專流」。
3. 工作流列表顯示階段數、任務數、關卡數、前置條件數。
4. 系統管理員可以新增工作流，至少包含 1 階段 1 任務；一般成員不能新增。
5. 系統管理員可以編輯自訂工作流的階段、任務、部門、工期、關卡。
6. 編輯工作流時，空名稱、沒有階段、沒有任務、未知部門、循環前置都會被拒絕。
7. 可複製內建工作流，副本可編輯、可刪除；內建工作流不可刪除。
8. 從工作流建立專案後，會產生 project、phase、task、deps、gates。
9. G2 pending 時，後續階段任務不能切到進行中，錯誤訊息包含「階段關卡未通過」。
10. 核准 G2 後，同一個後續任務可以切到進行中；若任務自己的硬性前置未滿足，仍會被既有前置規則擋住。
11. 375px 下工作流列表、編輯對話框、建立專案對話框、看板與任務頁沒有水平捲動。

整體測試仍用 `tests/records.html`，記錄 RED 與 GREEN 的 `#sum` 原文。
