# 子任務置頂回報卡 設計

- 日期：2026-10-01
- 範圍：`projectflow-full-demo.html`（單檔 Demo）
- 前置：F11 任務紀錄（`docs/superpowers/specs/2026-09-30-task-records-and-skip-design.md`）已完成
- 採用方案：B（回報卡固定在分頁上方，其他分頁在下面）

## 1. 問題

F11 把完成回報放在任務頁最後一個「紀錄」分頁，打開子任務時預設看到的是空的看板，最顯眼的按鈕是「＋ 新增子任務」。使用者不容易發現可以回報。

## 2. 目標

打開子任務就能看到回報的狀態和下一步動作。其他面板放在回報卡下面。

不在本次範圍：回報、確認、退回、跳過的邏輯（沿用 F11，不修改）；專案、階段、上層任務的版面。

## 3. 適用範圍

只套用在子任務：`n.type === 'task' && isLeaf(n)`，以下稱「葉任務頁」。其他節點的任務頁完全不變。

## 4. 置頂回報卡

新增 `reportCardHTML(n)`，回傳 HTML 字串。在 `pageNode()` 裡放在標題（`</header>`）之後、分頁列（`.toolbar`）之前，只在葉任務頁渲染。卡片用醒目的外框（與現有 `.panel` 區分，例如 accent 色邊框），不管目前在哪個分頁都會顯示。

依狀態顯示（由上往下，第一個符合的狀態生效）：

| 狀態判斷 | 卡片內容 | 動作按鈕 |
|---|---|---|
| `n.status === 'skipped'` | 「已跳過」、`skipInfo(n)` 的理由與核准人 | `can('override', n)`：「恢復任務」（`data-restore`） |
| 有待確認回報 `pendingReport(n.id)` | 「v{N} 等待確認」、結果、成果說明、自訂欄位、送出者與時間 | `can('override', n)`：「確認完成」（`data-rep-approve`）、「退回」（`data-rep-reject`）；否則顯示「等待 {approversFor(n)} 確認」 |
| `n.status === 'done'` 且有已核准回報 | 「已完成」、結果標籤、成果說明、自訂欄位、確認人與時間（自行確認標示「自行確認」） | 無 |
| `n.status === 'done'` 且沒有已核准回報 | 「已完成，未附回報」 | 無 |
| 最新一份回報為 `rejected` | 「已退回」、退回意見（醒目）、退回人 | `canReport(n)`：「重新回報」（`data-report`） |
| 其他（待辦／進行中） | 「完成回報」、需填欄位清單（結果、成果說明、實際完成日，加上 `fieldDefs(n.id)` 中必填的自訂欄位標籤）、「送出後由 {approversFor(n)} 確認」 | `canReport(n)`：「回報完成」（`data-report`） |

- 「已核准回報」與「最新回報」取該節點 `db.reports` 中 `version` 最大的對應筆。
- 沒有對應權限時只顯示內容，不顯示按鈕（協作、唯讀身分）。
- 按鈕沿用現有的 `data-report`、`data-rep-approve`、`data-rep-reject`、`data-restore` 事件處理，不新增事件。
- 結果、摘要、欄位、名稱、理由、意見等使用者文字一律經過 `esc()`。
- 卡片顯示結果摘要的部分抽成共用小函式，或沿用 `reportHTML` 的欄位格式，避免與 `reportHTML` 重複整段邏輯。

葉任務頁原本標題區的「⤳ 已跳過」提示與「恢復任務」按鈕，改由回報卡顯示，標題區不再重複（非葉任務維持原樣）。

## 5. 分頁

- 分頁順序：葉任務頁把「紀錄」放在第一個；其他節點維持原順序（紀錄在最後）。
- 預設分頁：`enter(id)` 進入葉任務時設 `ui.tab = 'records'`；進入非葉節點時，若 `ui.tab === 'records'` 則改為 `'board'`，其餘維持原分頁。
- 葉任務的「紀錄」分頁：
  - 「完成回報」區只列回報歷史（所有版本），標題改為「回報歷史（N）」，不再顯示「回報完成」按鈕、待確認提示與確認／退回按鈕（已移到回報卡）。沒有回報時顯示「還沒有回報紀錄。」
  - 筆記、附件區不變。
- 上層節點的「紀錄」分頁（彙總）不變。

## 6. 「＋ 新增子任務」

葉任務頁：標題區不再顯示主要按鈕「＋ 新增子任務」，改在分頁列右側（`.tools`）顯示次要樣式按鈕（`btn sm`），所有分頁都顯示，權限沿用 `can('create', n)`。非葉節點維持原樣。

## 7. 不變的部分

- 看板卡片上的「回報完成」按鈕、審核中心「待確認的完成回報」區塊。
- `submitReport`、`decideReport`、`skipTask`、`restoreTask` 等核心邏輯與資料結構（`db.v` 維持 3）。

## 8. 測試

在 `tests/records.test.js` 新增（瀏覽器測試頁 `tests/records.html`）：

1. `reportCardHTML` 各狀態：待辦（含必填自訂欄位「F0 值」與「回報完成」按鈕）、待確認（成員看到「等待」、主管看到確認／退回）、已退回（顯示意見與「重新回報」）、已完成有回報（顯示 F0 值）、已完成無回報、已跳過（主管有「恢復任務」）。
2. 唯讀或協作身分：卡片沒有任何動作按鈕。
3. `enter()` 進入葉任務 → `ui.tab === 'records'`；再進入上層 → `ui.tab === 'board'`。
4. 葉任務頁渲染結果：分頁列第一個是「紀錄」；標題區沒有 `btn primary` 的「＋ 新增子任務」，`.tools` 裡有；非葉節點仍是原本的順序與按鈕。
5. 回報卡的使用者文字經過 `esc()`（以含 `<b>` 的成果說明驗證）。

另以瀏覽器實測：阿明打開葉任務直接看到回報卡並送出；力瑜打開同一任務在卡片上確認完成；窄螢幕（375px）不出現水平捲動。

## 9. 文件更新

README 的 F11 段落補一句：子任務頁上方固定顯示回報卡，打開子任務預設進入「紀錄」分頁。
