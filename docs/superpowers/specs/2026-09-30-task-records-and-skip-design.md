# 任務紀錄（完成回報／筆記／附件）與主管跳過任務 設計

- 日期：2026-09-30
- 範圍：`projectflow-full-demo.html`（單檔 Demo）
- 採用方案：C（先在 Demo 確認介面與流程，資料結構照 PostgreSQL 設計，階段 4 再接真正後端）

## 1. 目標

1. 每個任務都能：回報完成、寫筆記、上傳附件。
2. 表單送出的資料結構化、可追溯，之後能直接搬進資料庫，讓 Agent 查詢。
3. 展示主管能跳過整個任務，以及成員申請跳過 → 主管核准的流程。

不在本次範圍：真正的後端與資料庫、全文檢索、檔案版本控制、Email 通知。

## 2. 介面位置

- 任務頁分頁列最後新增「紀錄」分頁（`ui.tab = 'records'`），在現有「成員與權限」之後。
- 葉節點任務：顯示回報區、筆記區、附件區，可操作。
- 上層節點（階段、有子任務的任務、專案）：唯讀彙總整棵子樹的回報、筆記、附件，每筆標示來源任務並可點擊進入該任務。
- 看板卡片（葉節點、狀態為待辦或進行中、且使用者可編輯）加上「回報完成」按鈕，直接開啟回報表單對話框。

## 3. 完成回報

### 3.1 欄位

固定欄位：

| 欄位 | 類型 | 必填 |
|---|---|---|
| 結果 | 選項：達成／部分達成／未達成 | 是 |
| 成果說明 | 多行文字 | 是 |
| 實際完成日 | 日期，預設今天 | 是 |
| 附件 | 多檔上傳 | 否 |

自訂欄位：

- 在任務編輯器新增「回報欄位」區塊，可新增、刪除、排序欄位。
- 欄位類型：`text`（文字）、`number`（數字，可填單位）、`date`（日期）、`select`（選項，逗號分隔）。
- 每個欄位可設為必填。
- 「另存為模板」會帶走各節點的回報欄位；「套用模板」會建立對應欄位。
- 範例資料：「第 1 次 F0 測試」（t3011）與同類 F0 測試任務設定「F0 值」（number，無單位，必填）；範例中已完成的 t3011 補一份已核准的回報，F0 值 = 2.6。

### 3.2 流程

```text
待辦／進行中 ──送出回報──▶ 審核中 ──確認完成──▶ 已完成
                              │
                              └──退回（意見必填）──▶ 進行中 ──重新送出──▶ 審核中（新版本）
```

- 送出權限：`can('edit', n)` 且節點為葉節點、狀態不是已完成或已跳過。
- 送出時檢查必填欄位；未滿足的硬性前置條件照現有規則阻擋（走現有的覆寫／跳過申請對話框）。
- 送出後回報鎖定，不能修改；每次送出為新版本（`version` 遞增），舊版本保留。
- 確認或退回權限：`can('override', n)`，也就是專案負責人，或負責範圍內的階段審核人。沿用現有 `approversFor(n)` 顯示可審核的人。
- 確認完成：回報狀態 `approved`，任務狀態 `done`，觸發現有的解鎖後續任務與通知。
- 退回：回報狀態 `rejected` 並記錄意見，任務回到 `doing`，通知送出者。
- 有審核權限的人自己送出回報時，對話框多一個「送出並直接確認」按鈕，一步完成，稽核紀錄註明「自行確認」。
- 審核中心新增「待確認的完成回報（N）」區塊，列出任務、送出者、結果、摘要，並附確認／退回按鈕。側邊欄的待審數量計入這一項。
- 在看板把卡片從「審核中」直接拖到「已完成」時：若有待確認回報，視同「確認完成」（需權限）；若沒有回報，照現有行為直接完成，不強制回報。

## 4. 筆記

- 以時間軸排列（新的在上），顯示作者、時間，作者修改過會標示「已編輯」。
- 新增權限：`can('edit', n)`。修改權限：只有作者本人。
- 修改時舊內容寫入稽核紀錄；筆記不提供刪除。
- 筆記可附附件。
- 原有的 `n.note`（備註）保留不動，仍顯示在任務標頭。

## 5. 附件

- 可附在任務、某份回報或某則筆記上（`report_id`／`note_id` 擇一或皆空）。
- 列表欄位：檔名、大小、上傳者、時間、所屬（任務／回報 vN／筆記）。
- 圖片與 PDF 可在新分頁預覽，其他類型下載。
- 單檔上限 10 MB，超過時提示且不上傳。
- 刪除：上傳者本人或 `can('delete', n)`；軟刪除（設定 `deleted_at`），寫入稽核紀錄，列表不再顯示。已鎖定回報的附件不能刪除。
- Demo 儲存：中繼資料存在 `db.attachments`（localStorage），檔案內容以附件 id 為 key 存在 IndexedDB（資料庫 `projectflow-files`，store `blobs`）。
- IndexedDB 無法使用時：附件區顯示「此瀏覽器無法儲存檔案」，上傳按鈕停用；回報與筆記照常可用。
- 「重置資料」時一併清空 IndexedDB。
- 計算 SHA-256（`crypto.subtle`）存入 `sha256`，供之後去重與完整性檢查。

## 6. 主管跳過整個任務

- 入口：任務編輯器新增「跳過任務」按鈕；看板卡片的 ✎ 旁加「⤳」跳過按鈕（未完成且非已跳過時顯示）。
- 對話框：顯示將受影響的內容（本身，以及所有未完成的子孫任務；將解鎖的後續任務），理由必填。
- 有 `can('override', n)` 權限：直接執行。本身與所有未完成的子孫節點狀態設為 `skipped`，寫入 `db.overrides`（`kind: 'task'`、`status: 'approved'`、`self: true`）與稽核紀錄，觸發解鎖與通知。
- 沒有權限：送出跳過申請（`kind: 'task'`、`status: 'pending'`），通知可核准的人。進入審核中心現有「待審核的跳過申請」清單，標示「整個任務」；核准後執行上述動作，退回則通知申請人。
- 已跳過的卡片顯示「已跳過」標籤，滑過顯示理由與核准人。
- 恢復：有 `can('override', n)` 權限者可在任務頁按「恢復任務」，本身與同一次跳過的子孫節點回到跳過前的狀態（跳過時把原狀態存在 override 紀錄的 `prev` 裡），並寫入稽核紀錄。
- 已跳過的任務可以寫筆記、上傳附件，但不能送出完成回報。
- 審核中心空白提示改為示範情境：「用『阿明（成員）』開啟任務 → 跳過任務 → 送出申請，再切換成『力瑜』核准。」

## 7. 資料模型

Demo 內的 `db` 結構（欄位名稱與之後的 PostgreSQL 資料表一致）：

```text
db.reportFields[]   id, node_id, key, label, type(text|number|date|select),
                    unit, options[], required, order
db.reports[]        id, node_id, version, result(met|partial|unmet), summary,
                    finished_on, fields[{ key, label, value, unit }],
                    status(submitted|approved|rejected),
                    submitted_by, submitted_at, reviewed_by, reviewed_at,
                    review_comment, self_approved
db.notes[]          id, node_id, body, author, created_at, edited_at
db.attachments[]    id, node_id, report_id, note_id, filename, mime, size,
                    sha256, storage_key, uploaded_by, uploaded_at, deleted_at
db.overrides[]      現有欄位 + kind(dep|gate|task)、prev{ node_id: status }
```

- 模板節點新增 `fields`（回報欄位定義），套用時依新節點 id 建立 `reportFields`。
- 回報的 `fields` 同時存標籤與單位的快照，欄位定義之後被改也不影響舊回報的解讀。
- 刪除節點時一併刪除該子樹的 reportFields、reports、notes，並軟刪除附件。
- 資料版本：`db.v` 由 2 升為 3。載入 v2 資料時補上空陣列、為既有 overrides 補 `kind`（`gate: true` → `gate`，其餘 → `dep`），並補範例的 F0 欄位與回報。

## 8. Agent 查詢（Demo 示範）

- AI 副手現有的「專案問答」可引用內容，加入該專案的已核准與待確認回報（結果、摘要、自訂欄位）與筆記。
- 依節點的資料分級處理：機密節點的內容不送出，內部資料照現有規則遮罩後送出。
- 附件只提供檔名與所屬，不送出內容。

## 9. 稽核與通知

以下動作都寫入稽核紀錄：送出回報、確認完成、退回、新增筆記、修改筆記（含舊內容）、上傳附件、刪除附件、跳過任務、申請跳過、核准或退回跳過申請、恢復任務。

其中需要別人處理或會影響別人的動作另外產生通知：送出回報（通知可確認的人）、確認或退回（通知送出者）、申請跳過（通知可核准的人）、核准或退回跳過申請、跳過後解鎖的後續任務。筆記與附件只記錄，不發通知。

## 10. 驗證情境（瀏覽器實測）

1. 阿明開啟自己的葉節點任務 → 送出回報（含附件與必填自訂欄位）→ 任務變審核中。
2. 力瑜在審核中心退回並填意見 → 任務回到進行中 → 阿明重新送出 → 出現 v2。
3. 力瑜確認完成 → 任務已完成、後續任務解鎖、通知出現。
4. 阿明對任務申請跳過 → 陳主管（範圍內）或力瑜核准 → 任務已跳過、進度 100%。
5. 力瑜直接跳過一個有子任務的上層任務 → 未完成的子任務全部已跳過 → 恢復任務後回到原狀態。
6. 上層節點「紀錄」分頁正確彙總子樹資料。
7. 超過 10 MB 的檔案被擋下；重新整理後回報、筆記、附件仍在；重置資料後全部清空。
8. 以 v2 的舊 localStorage 資料載入，自動轉換且沒有錯誤。
9. 協作人員與唯讀身分看不到未被指派節點的紀錄，也不能送出。
