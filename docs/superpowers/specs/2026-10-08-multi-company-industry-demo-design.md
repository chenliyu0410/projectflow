# W6 多公司產業範例設計

## 1. 背景與問題

目前 `projectflow-full-demo.html` 的核心功能已能展示專案樹、看板、時程、相依、關卡、權限、回報、文件、AI 副手與研發營運資料，但種子資料、成員、部門與營運欄位都以寵物食品製造公司為主。展示者很難直接證明 ProjectFlow 能套用到其他產業。

W6 要把單公司 Demo 擴充成五個固定的產業範例公司。五家公司在同一個單檔 Demo 中切換，但資料、身分、權限、稽核與附件彼此隔離。這是展示用途的瀏覽器內公司空間，不等同正式產品的多租戶架構。

本設計依 PROGRESS D44、D45，以及 2026-10-08 人類逐段確認的 brainstorming 結論定稿。

## 2. 目標

W6 完成後應達成：

1. 左下角在身分切換上方提供公司選單，可在五家公司間切換。
2. 每家公司有獨立的專案、工作流、部門、成員、權限設定、營運資料、稽核紀錄、目前身分與附件命名空間。
3. 每家公司至少有一個完整主專案、一個精簡次專案、1～2 套工作流，以及能和專案節點連動的產業營運資料。
4. 切換公司後，導覽、專案、身分、權限、營運資料、搜尋與 AI 副手都只使用目前公司的資料。
5. 現有 v2～v5 瀏覽器資料升級後完整保留在寵物食品公司。
6. 五家公司在重新整理頁面後都能保留各自的修改。
7. 既有 Demo 行為與 149 項測試在寵物食品公司空間中不得回歸。

## 3. 不在範圍

- 不提供公司新增、刪除、改名、排序或自訂品牌功能。
- 不提供跨公司搜尋、跨公司總覽、跨公司指派或資料搬移。
- 不提供正式登入、邀請、帳號與公司關聯管理。
- 不把公司選單當成安全邊界；它是 Demo 體驗控制。正式產品仍須在 API 與資料庫以 `organization_id` 做授權隔離。
- 不建立後端、同步服務或真正 ERP／DevOps／工程系統串接。
- 不修改 `projectflow-petfood-demo.html`。
- 不在 W6 處理 D43 的工作流表單編輯器。

## 4. 使用者體驗

### 4.1 左下角公司切換

左下角資訊區由上到下顯示：

1. 公司選單標籤「切換公司（Demo，用來體驗不同產業）」。
2. 公司選單；每個選項顯示「公司名稱｜產業」。
3. 目前使用者頭像、姓名與職稱。
4. 原有的身分切換選單。
5. 「重置目前公司」按鈕。

公司選單固定包含五家公司，不提供新增或刪除入口。所有公司名稱、產業、成員名稱與其他輸出到 HTML 的文字都必須先經過 `esc()`。

### 4.2 切換流程

使用者選擇另一家公司時依序執行：

1. 把目前公司的 `db`、`audit` 與目前身分寫回公司空間。
2. 將整個 v6 容器寫入既有 localStorage key `projectflow-demo-v2`。
3. 儲存失敗時停止切換，保留原畫面並顯示明確錯誤。
4. 載入目標公司的 `db`、`audit`、成員、欄位權限與產業設定。
5. 將目標公司的目前身分設為 `defaultUserId`（預設專案負責人）；若不存在，使用該公司第一個成員。
6. 回到「所有專案總覽」，並把目前節點設為該公司第一個可見專案。
7. 關閉抽屜與對話框，清除拖曳／連線／營運資料選取／AI 對話／復原堆疊等暫存狀態。
8. 重新渲染並顯示「已切換至〈公司名稱〉」提示。

切換公司不需確認，因為成功切換前必須先完成自動儲存。切回原公司時應看到原先修改後的內容，但身分會回到該公司的預設專案負責人。只有重新整理同一家公司、沒有切換公司時，才保留該公司目前身分。

### 4.3 重置目前公司

「重置目前公司」必須先顯示確認對話框，清楚寫出公司名稱與只影響目前公司的範圍。確認後：

- 只以該公司的種子資料重建 `db`、`audit` 與目前身分。
- 只刪除該公司 metadata 列出的 IndexedDB 附件內容。
- 不改動其他四家公司的資料、附件或目前身分。
- 清除暫存 UI 與復原堆疊，回到該公司的第一個專案。
- 寫回 localStorage，成功後顯示完成提示；失敗時顯示錯誤。

W6 不提供「重置全部公司」按鈕。

## 5. 資料架構

### 5.1 v6 公司容器

localStorage key 維持 `projectflow-demo-v2`。儲存物件升為 v6，概念結構如下：

```js
{
  v: 6,
  activeCompanyId: 'petfood',
  companies: {
    petfood: {
      id: 'petfood',
      name: '毛研食品',
      industry: '寵物食品製造',
      defaultUserId: 'yu',
      me: 'yu',
      users: { /* 公司成員 */ },
      fieldAccess: { /* 欄位權限 */ },
      opsConfig: { /* 營運資料模組與顯示設定 */ },
      db: { v: 6, /* 既有 db 欄位與產業資料 */ },
      audit: { /* acts / ai / sync / notes */ }
    }
  }
}
```

執行期間保留既有全域介面：`db` 與 `audit` 指向目前公司的物件；成員、欄位權限與產業設定改成可由目前公司重新綁定的執行期參照。公司空間的 `me` 用於重新整理同一家公司時恢復身分；透過公司選單進入另一家公司時，改寫為該公司的 `defaultUserId`。既有功能應透過目前公司參照運作，不得在各函式自行掃描其他公司。

公司空間中的 `db.v` 也必須是 6，讓既有測試與資料版本檢查仍有單一答案。`commit(label, fn)`、`log(nodeId, action, text)`、`can(action, node)` 的既有責任不變，全部只作用於目前公司。

### 5.2 v2～v5 升級

`load()` 必須接受 v2、v3、v4、v5、v6：

1. v2～v4 先依既有順序升級到 v5。
2. 把升級後的既有 `db`、`audit` 與 `me` 原樣放入 `petfood` 公司空間，只補 v6 所需欄位，不重建或覆寫使用者資料。
3. 建立另外四家公司的全新種子空間。
4. `activeCompanyId` 設為 `petfood`。
5. 每家公司 `db.v` 與容器 `v` 都設為 6，再保存一次。

若讀到合法 v6，但 `activeCompanyId` 不存在，改用 `petfood`；若只有某一家公司的資料缺漏或損壞，只重建該公司並提示，不清除其他公司。整個 JSON 無法解析時才回到全新五家公司種子資料，並顯示資料重建提示。

### 5.3 公司內 ID 與附件 key

一般節點、成員、部門與營運紀錄 ID 只需在同一家公司內唯一；不同公司可使用相同流水號，因為查詢不得跨公司。

新附件的 IndexedDB `storage_key` 必須加公司前綴：

```text
<companyId>:<attachmentId>
```

例如 `software:at1042`。從 v2～v5 遷移的毛研食品附件保留原 `storage_key`，確保既有 blob 仍可開啟；後續新附件才使用前綴。重置目前公司時依該公司 `db.attachments[].storage_key` 逐筆刪除，不可呼叫清空整個 object store 的操作。

### 6.1 每家公司最低內容

每家公司都必須具備：

- 一個能展示多階段、相依、Gate、回報與稽核的完整主專案。
- 一個至少包含兩個階段與數個任務的精簡次專案。
- 1～2 套可在模板庫檢視並建立專案的工作流。
- 至少一筆營運資料連到主專案節點，且至少一個狀態或事件能影響專案提示、前置條件或 Gate。
- 獨立部門與成員；至少涵蓋專案負責人、階段審核人、成員、協作人員與系統管理員，並至少有一位部門主管。
- 至少一筆完成回報或筆記，以及一筆可在稽核頁看到的事件。

毛研食品必須盡量保留現有種子資料、既有使用者 ID 與測試錨點。其他四家公司使用自己的 ID 前綴或公司內 ID，不依賴毛研食品的 `USERS`、部門或欄位權限。

### 6.2 產業化部門

部門名稱要符合各產業，不得把所有公司都套成「研發／製程／品保」：

- 毛研食品：沿用現有 10 部門。
- 峰曜科技：產品企劃、硬體研發、工業設計、採購、品保、製造、認證、業務、資訊、財務。
- 光點企劃：策略企劃、創意、客戶服務、活動製作、媒體、公關、採購、財務、資訊。
- 雲序軟體：產品、前端、後端、品質保證、DevOps、資安、客戶成功、業務、資訊。
- 築衡工程：專案管理、設計、機電、採購、工務、品管、職安、財務、行政、資訊。

## 7. 產業化營運資料

左側導覽的「研發營運資料」改名為「營運資料」。目前公司的 `opsConfig` 決定分頁名稱、欄位、資料、空狀態與專案連結文字。

營運資料必須採設定驅動：渲染與查詢根據目前公司的模組設定，不得以五段大量 `if (companyId === ...)` 分別產生整頁。每個模組至少定義：

- `id`、顯示名稱與說明。
- 欄位 key、繁體中文標籤、顯示型態與是否受欄位權限控制。
- 紀錄陣列與可選的專案節點連結。
- 狀態標籤、日期或進度等共通顯示資訊。
- 若會影響專案，定義事件文字與目標節點／Gate，不在渲染函式硬編公司名稱。

節點的營運資料連結沿用 `{ t, id }` 形狀；`t` 對應目前公司 `opsConfig` 的模組 ID。毛研食品既有的 `supplier`、`formula`、`po`、`wo` 等 `t` 值繼續有效。找不到模組或紀錄時顯示安全的「資料不存在」提示，不拋例外。

既有毛研食品的配方版本、採購交期、工單與追溯展示不可因通用化而消失。其他公司至少要提供設定驅動的列表、詳情、專案連結與一個產業事件示例，不要求在 W6 重做完整 ERP 編輯器。

## 8. 身分、權限與資料隔離

- `me()`、`uname()`、`dept()`、`can()`、`canWork()`、`visible()`、欄位權限與審核人查詢都只能讀目前公司的成員與部門。
- 公司切換後，身分選單只列該公司成員。
- 專案、我的任務、審核中心、模板庫、文件、紀錄、營運資料、AI 政策、AI 回答與稽核頁都只能讀目前公司。
- 公司 A 的節點 ID 即使和公司 B 相同，也不得因全域查詢而互相命中。
- 權限仍使用既有 `can(action, node)`／`canWork(node)` 規則；W6 不新增正式跨公司角色。
- 公司選單本身不需要管理員權限，因為它是 Demo 展示控制，而不是正式授權操作。
- 所有會修改目前公司 `db` 的動作仍包在 `commit(label, fn)`，並依既有規則呼叫 `log()`。

## 9. 暫存 UI 與復原

公司切換後不得保留會指向舊公司資料的暫存狀態，包括：

- `undoStack`
- 目前節點、分頁、營運資料選取與追溯選取
- 相依連線模式、時間軸部門篩選與展開狀態
- AI 對話內容
- 開啟中的 drawer、dialog 與行動版側欄

切換後預設進入「所有專案總覽」。復原只允許復原目前公司在切換後產生的動作，不能跨公司復原。

## 10. 錯誤處理

- localStorage 寫入失敗：顯示「資料無法儲存，尚未切換公司」，維持目前公司與畫面。
- v6 的單一公司資料缺漏：只用該公司種子補回，其他公司不變，並顯示提示。
- 目前身分不在該公司：改用 `defaultUserId`；若仍不存在，使用第一個成員並記錄 console warning，不讓畫面拋例外。
- 公司沒有使用者可見的專案：沿用既有空狀態，不帶入其他公司的專案。
- IndexedDB 不可用：沿用既有附件警告；其他公司切換與非附件功能仍可使用。
- 找不到舊附件 blob：沿用既有「找不到檔案內容」提示，不刪 metadata。
- 產業模組或連結不存在：顯示空狀態或「資料不存在」，不得出現 `undefined`、`NaN` 或 console error。

## 11. 測試與驗收

實作依 WORKFLOW §3 與 §5 用 TDD 進行。新增 `tests/companies.test.js`，並由 `tests/records.html` 載入；確切新增測試數在 plan 以「基準 + N」表示。

### 11.1 自動化測試

至少覆蓋：

1. 種子資料是 v6 且固定有五家公司，名稱與產業正確。
2. v2、v3、v4、v5 都能升級到 v6，既有節點、稽核、目前身分與舊附件 key 保留於毛研食品。
3. 切換公司會更新專案、成員、部門、工作流與營運模組，並把身分設為目標公司的預設專案負責人。
4. 公司 A 的修改在切換與重新載入後仍存在，公司 B 不受影響。
5. 相同節點 ID 或附件 ID 在不同公司不會交叉讀取。
6. 新附件 storage key 含公司前綴；舊毛研食品附件 key 仍可查詢。
7. 重置目前公司只重建該公司，其他公司資料與附件 metadata 不變。
8. 切換後的身分、權限、可見性、AI 回答與稽核只使用目前公司資料。
9. 每家公司都符合 §6.1 的最低內容，營運資料連結不出現失效 ID。
10. localStorage 寫入失敗時不切換公司。
11. 單一公司缺漏時只補回該公司。
12. 原有 `records.test.js`、`departments.test.js` 全部在毛研食品空間通過。

### 11.2 UI 驗收

在桌面與 375px 寬度逐家驗證：

- 公司選單位於身分切換上方，選項文字完整且不溢出。
- 切換五家公司後，公司名稱、專案、身分、部門、工作流與營運分頁正確。
- 每家公司打開主專案的看板、時程、成員、紀錄與營運資料，無 `undefined`、`NaN` 或錯誤公司內容。
- 375px 沒有水平捲動，選單與按鈕不重疊。
- console 沒有非字型網路造成的 error。
- 實測修改公司 A、切換 B、再切回 A 的持久化流程。
- 實測「重置目前公司」不影響另一家公司。

## 13. 正式產品銜接

W6 的五家公司是瀏覽器內固定展示空間。正式產品恢復 P0／P1 規劃時，資料模型至少要保留 `organization_id`／公司邊界需求，並在 API、資料庫查詢、檔案儲存與權限檢查中強制隔離；不得把「切換前端全域參照」當成正式安全機制。
