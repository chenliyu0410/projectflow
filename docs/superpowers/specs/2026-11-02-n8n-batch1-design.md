# N8N 第一批：通知外送與 AI 週報設計

日期：2026-11-02。程式基準：`960de38`。依據：[PROGRESS §2 N8N／D83](../../PROGRESS.md)、README F8／F9／F11、§8.2「Email／Teams 通知」、§8.5「週報改由 LLM 產生」。

**狀態：G1 規格待使用者審閱。** 下列設計已與使用者逐段確認（2026-11-02 brainstorming）。

## 1. 目標與範圍

解決「主管常追問這週大家做了什麼、接下來要做什麼」：站內通知轉寄 Email、每人每日摘要、每個專案的 AI 週報（負責人確認後寄全組）。以地端自架 n8n 負責排程與寄信，專流負責資料、權限、AI 與稽核。

已決定（使用者原話或選項）：

| 題目 | 決定 |
|---|---|
| 目的 | C：先做展示用（Mailpit 假信箱、`帳號@demo.local`），架構照正式方式設計，換 SMTP 設定即可上線 |
| 哪些通知寄 Email | A：現有 5 種站內通知全部轉寄＋每日提醒；每人一個總開關 |
| 週報單位與收件人 | A：每個專案一份，負責人確認後寄給管理角色（D84「A 只寄管理角色」，見 §4）；每日摘要每人一封 |
| 負責人怎麼確認 | A：在專流「週報」分頁修改並按「確認寄出」，稽核留在專流 |
| 排程 | C：固定時間（週五 17:00 週報草稿、週一至五 09:00 每日摘要，Asia/Taipei）＋「立即產生草稿」按鈕 |
| AI 放哪裡 | 做法 2：AI 在專流內，用既有本地模型設定；n8n 只排程與寄信 |

**不做**：Teams／LINE 等需外網管道；逐種通知設定；每專案自訂排程；正式 SMTP 退信處理；ERP 轉接層（使用者決定不做）；第二批（文件收件＋OCR、Excel 匯入）與第三批（排程維運）。

## 2. 已核對的現況

| 項目 | 現況 | 設計影響 |
|---|---|---|
| `users` | 無 Email 欄位 | 新增 `email`、`email_notify` |
| 站內通知 | 全部經 `notification_service.emit()` 產生，有 `event_key` 去重 | 在 `emit()` 寫入通知的同一交易寫 outbox 事件 |
| 認證 | 只有 cookie session（`auth.require_session`） | 新增服務帳號 Bearer token，只限白名單 API |
| 本地模型 | `ai.model.settings(company)`、`model.chat(config, system, prompt, schema)` | 週報 AI 沿用，不另設 Ollama 位址 |
| 資料分級 | `ai.policy.Resolver` 計算節點等級 | 週報排除機密節點 |
| 前置阻擋 | `notification_service.states()` 判斷 hard 前置 | 「卡住」沿用 |
| 部署 | `deploy/docker-compose.yml` 有 db、api、web | 新增 n8n、mailpit 服務 |

## 3. 架構

```
┌──────────── Docker Compose（只綁 127.0.0.1）──────────────┐
│  n8n ──每分鐘拉事件／呼叫 API（Bearer token）──▶ 專流 API  │
│   │                                               │       │
│   └──SMTP──▶ Mailpit（Demo 假信箱）               └─▶ 地端 Ollama │
└───────────────────────────────────────────────────────────┘
```

方向統一為「n8n 呼叫專流」：專流不保存 n8n 位址、不需背景推送程式；n8n 停機期間事件留在專流，啟動後補寄。通知延遲最多約 1 分鐘。

### 3.1 專流新增

| 元件 | 內容 |
|---|---|
| 使用者 Email | `users.email`（可空）、`users.email_notify`（預設 true）。展示資料填 `<username>@demo.local`。個人設定可改自己的 Email 與開關 |
| 服務帳號 token | 表 `api_tokens`：名稱、SHA-256 雜湊、建立者、建立／最後使用／停用時間。管理者建立，完整 token 只顯示一次。`Authorization: Bearer` 驗證，只能呼叫 §3.3 白名單，其他回 403，不能登入網頁 |
| 事件外送 | 表 `outbox_events`：唯一 id、類型、收件人、內容（主旨、本文、專流連結）、狀態（pending／sent／failed）、嘗試次數、最後錯誤 |
| 週報 | 表 `weekly_reports`：專案、週起日、狀態（draft／sent／unsent）、AI 原稿、修改後文字、程式整理資料（JSON）、收件人快照、排除數、模型名稱或「AI 未啟用」、產生者、確認者與時間 |
| 前端 | 專案「週報」分頁（草稿、編輯、立即產生、確認寄出、歷史）；個人設定 Email 與通知開關；管理者 token 管理頁與失敗事件清單 |

資料變更以一次 migration 完成（`users` 兩欄＋三張表；只新增，舊帳號 `email_notify` 為 true、`email` 為空）。

### 3.2 n8n 流程（匯出 JSON 進 repo，`deploy/n8n/`）

1. **通知轉寄**：每分鐘 → 拉待送事件 → 依 Email 寄信 → 回報已送出或失敗
2. **每日摘要**：週一至五 09:00 → 讀每日摘要 → 每人一封
3. **週報草稿**：週五 17:00 → 呼叫「產生草稿」（全部專案）

寄給負責人的「草稿待確認」與確認後寄全組的「週報」都由專流寫成 outbox 事件，經流程 1 寄出，不另設流程。

n8n 使用自己的 SQLite volume；關閉使用統計、版本檢查、範本庫（`N8N_DIAGNOSTICS_ENABLED=false`、`N8N_VERSION_NOTIFICATIONS_ENABLED=false`、`N8N_TEMPLATES_ENABLED=false`），時區 `GENERIC_TIMEZONE=Asia/Taipei`。token、SMTP 等設定放 `deploy/.env`，不進 git。禁止使用 n8n 雲端 AI 節點。

### 3.3 Token 白名單 API

| API | 用途 |
|---|---|
| `GET /integrations/events?limit=` | 讀待送事件 |
| `POST /integrations/events/{id}/result` | 回報 sent 或 failed（附錯誤） |
| `POST /integrations/weekly-reports/generate` | 為全部或指定專案產生本週草稿 |
| `GET /integrations/daily-digest` | 讀每人每日摘要 |

所有呼叫寫稽核，執行者記為該服務帳號。

## 4. 週報內容

統計期間：本週一 00:00 至產生當下（Asia/Taipei）。

**程式整理（數字與清單由程式算，負責人不能改）**

| 區塊 | 規則 |
|---|---|
| 本週完成 | 本週有 F11 回報且狀態 approved：任務、負責人、結果、成果說明 |
| 待確認 | 本週送出、狀態 submitted 的回報 |
| 進行中 | 節點狀態 `doing`：到期日、進度 |
| 下週到期 | 未來 7 天到期且未完成 |
| 逾期 | 已過到期日且未完成 |
| 卡住 | 被 hard 前置擋住（沿用現有判斷） |
| 本週未回報成員 | 負責進行中或逾期任務，但本週無回報也無筆記的人 |

**收件人（D84）**：專案負責人，加上在此專案有負責或協作任務、且角色為 admin／project_owner／reviewer／readonly 的啟用中帳號。一般成員（member）只看得到自己範圍的任務，不收週報，由每日摘要涵蓋。

**權限與分級**：產生時記收件人快照。任務須每位收件人都看得到（`can_view_node`）且非機密才列入；被排除數量提示負責人（「有 N 項因權限或機密等級未列入」），不列名稱。確認寄出時重新檢查：已停用或已看不到列入任務的人移出名單並提示。

**AI 撰寫**：把程式整理的資料交給本地模型，以固定 schema 輸出四段：整體摘要、本週重點、風險與卡關、下週重點。提到清單外任務的段落捨棄。結果寫入 AI 稽核（功能、模型、本地處理）。

**週報組成**：「AI 建議」標示 → AI 四段（可修改）→ 程式整理的數字表與清單（不可修改）。

## 5. 每日摘要

每人一封，週一至五 09:00：我負責的任務中昨天完成、今天到期、已逾期、卡住。不使用 AI。四類皆空不寄；只寄啟用中、有 Email、開關開啟者。內容依個人權限過濾。

## 6. 錯誤處理與安全

| 狀況 | 處理 |
|---|---|
| 寄信失敗 | 事件保持 pending，下一輪重試；失敗 5 次標 failed、不再重試，顯示在管理者頁 |
| n8n 重複拉到同一事件 | 以事件 id 去重，已 sent 不再寄 |
| 本地模型未開或逾時 | 仍產生草稿，只放程式整理，標「AI 未啟用，以下為原始整理」 |
| AI 格式錯誤或提到清單外任務 | 該段改用原始整理 |
| 同專案同週重複產生 | 一份草稿；手動產生覆蓋未寄出草稿，已寄出不可覆蓋 |
| 負責人未確認 | 草稿保留，不自動寄；下週新草稿產生時舊的標 unsent |

信件本文只放摘要與專流連結，不放附件、檔案內容或機密欄位；使用者文字先 HTML 跳脫。Demo 環境所有信件只送 Mailpit。立即產生與確認寄出只限專案負責人與管理者。

## 7. 測試與驗收

依 TDD，先寫失敗測試再實作，各工具記實際 exit code。

- **pytest**：token 白名單、403、雜湊、停用失效；通知與事件同交易、重複拉取只寄一次、5 次失敗停止；週報七區塊規則、收件人交集、排除機密、模型未開退回、清單外任務捨棄、已寄出不可覆蓋、確認時重驗收件人；每日摘要空不寄、開關、停用帳號。用假模型，不需 Ollama。
- **Vitest**：週報分頁（草稿、編輯、立即產生、確認寄出、歷史、非負責人看不到操作）；個人設定 Email 與開關；token 管理頁。
- **n8n 驗證腳本**：啟動 Compose → 匯入流程 → 觸發事件 → 以 Mailpit API 檢查收信。

**Demo 驗收路徑（單機離線）**

1. 指派任務給 chen → Mailpit 約 1 分鐘內收到「你被指派為任務負責人」
2. n8n 手動執行每日摘要 → 每人收到當日摘要
3. yu 在「週報」按立即產生 → 看到 AI 草稿、數字表與「未列入 N 項」→ 改一句後確認寄出 → 全組收到
4. 稽核可查草稿產生者、模型、確認者與時間
5. 停掉 n8n 後指派任務 → 重啟 n8n → 補寄成功
