# 正式版 Demo 功能移植路線圖

日期：2026-10-09更新（D69、D70）。後續優先做到與Demo相同畫面及操作，並先補齊任務規劃器功能，其他模組分批補齊。

本文件是範圍與順序提案，不是可直接執行的 implementation plan，也不表示新 spec、權限規則或 migration 已核准。進度只記在 PROGRESS。P2a至P2d是本輪移植工作ID，不等同README舊階段1至9。

## 目標與現況

目前P2a／P2b／P2c精簡版及UI1／UI2已交付，15套模板都有進行中的展示專案；介面尚非Demo完整一致。新主線見[Demo畫面與操作優先規劃](superpowers/plans/2026-10-09-demo-parity-first.md)。以下P2各節保留為功能範圍索引，不代表接下來先做後端。

目標是讓正式版逐步具備 Demo 的可見操作與核心功能，資料由正式API／PostgreSQL管理，不搬入假的備份、ERP同步或AI連線狀態。

已具備真登入／公司隔離、任務編輯／日期、回報審核／筆記附件、Gate／FS、日週月時程、模板與稽核介面。文件／營運／AI等完整模組和進階排程尚未交付；既有人類試用簽核維持未完成。

## 順序與共同規則

目前順序（D70修訂D69）：已完成P2a/b/c、UI1/2 → **UI3框架與首頁 → UI4工作區與操作 → TP-A至TP-G任務規劃器功能補齊 → UI5文件／資料／營運／AI畫面 → F1逐頁補正式功能 → F2跨頁一致性與剩餘差距**。原P2d拆入UI5/F1，不再作為下一個大型後端階段；每批獨立交付15173。TP各批範圍見[D70：任務規劃器優先](superpowers/plans/2026-10-09-demo-parity-first.md#d70任務規劃器優先)；文件不算在任務規劃器內，復原只做上一步。

- 2026-10-09起依D65精簡流程：每階段一份短規格／計畫、一次獨立審查、一次完整回歸及一次交付紀錄；修正只驗受影響部分，詳見[WORKFLOW §14](WORKFLOW.md#14-精簡流程d65)。
- 畫面／互動可先交付；已有真功能直接接，未完成後端可在明確展示預覽中呈現，隔離示例不能混入正式資料。畫面對齊與正式功能分開驗收，不用假成功訊息代替API。
- 保留既有資料與Demo；新欄位使用migration，不重設資料庫、不刪歷史專案。
- 公司與角色權限由API強制執行，彙總也不得洩漏隱藏節點。
- 自動驗收只用隔離Compose；15173保留供人類試用。
- 桌面1280與手機375均驗證；含載入、空資料、失敗重試、無權限與登入失效狀態。
- 各階段獨立審查與驗收後按既有ff-only／D50發布規則交付；人類簽核不由AI代勾。

## P2a：完整任務操作與工作區

第一個可見里程碑：從精簡驗證頁變成可日常操作的專案工作區。

| 任務 | 交付 |
|---|---|
| A1 工作區與導覽 | 專案總覽、我的任務、專案工作區；保留登入與登出，手機可用的導覽 |
| A2 任務資料與編輯API | 名稱、負責人、部門、起迄日期；驗證日期、公司關聯、寫入權限與稽核；保留舊資料的migration |
| A3 任務新增／編輯介面 | 在專案或節點下新增任務、編輯既有任務；明確顯示儲存中／成功／失敗，支援取消 |
| A4 多層節點工作區 | 樹狀展開／收合、路徑、節點詳情與下一層看板；保留Gate阻擋／核准 |
| A5 總覽與我的任務 | 可見範圍的專案／任務統計、本人任務跨專案列表、搜尋與狀態篩選、點擊進入任務 |
| A6 整合交付 | 真實角色與跨公司測試、桌面／手機走查、重開持久化、部署與文件更新 |

驗收：管理者新增含至少四層節點的專案內容；有權限者編輯任務資料、重新登入仍保留；成員從我的任務進入本人任務；唯讀與其他公司無法寫入。日期是日期欄位，不宣稱已有拖曳時程。

需在spec定案：新增／改派與一般編輯的權限矩陣、父節點可建立的種類、日期可空及合法範圍、進度彙總算法。不能把Demo既有安全缺口直接移植。

## P2b：回報與協作

第二個可見里程碑：任務不只是改狀態，而能留下工作內容、送審與追蹤歷程。

| 任務 | 交付 |
|---|---|
| B1 回報與審核流程 | 核對現有Report API，補足送出、確認、退回、歷史與狀態轉換的服務／權限／稽核 |
| B2 任務回報介面 | 任務紀錄分頁、完成回報表單、回報歷史、待審核／退回後操作 |
| B3 筆記與協作 | 筆記新增與權限、協作人員／部門及可見性；協作人的我的任務入口 |
| B4 任務附件 | 上傳、下載、移除與筆記／回報關聯；主機儲存、公司隔離、容量／類型限制與失敗處理 |
| B5 審核中心與稽核 | 待確認回報、Gate；規格確定後補跳過／覆寫申請；稽核查詢與篩選 |
| B6 整合交付 | 成員送回報→主管退回→修改重送→確認；附件越權拒絕、真實桌面／手機驗收 |

驗收：完成一次可追溯的回報／審核與筆記附件流程；每次業務寫入有稽核，成員與主管只能執行允許的操作。附件不使用瀏覽器IndexedDB假裝多人儲存。

需在spec定案：確認／退回後是否鎖定、筆記編輯權、附件限制、協作可見性、跳過／覆寫授權；既有Report submit API不等於完整審核已完成。

## P2c：時程與流程工具

第三個可見里程碑：使用者能安排日期、重用流程並辨識阻塞。

| 任務 | 交付 |
|---|---|
| C1 時程讀取 | 多層時程、展開／收合、日／週／月、今天標線、里程碑與任務側欄 |
| C2 時程編輯 | 日期側欄、拖曳移動／拉伸、手機可替代操作；改期稽核與可復原行為 |
| C3 模板管理 | 工作流模板新增／編輯／複製；任務子樹另存／套用、相對日期；保持Gate一致 |
| C4 前置條件服務 | 多個前置、FS／SS／FF與延遲、循環偵測、硬性／軟性阻擋、授權覆寫 |
| C5 相依呈現 | 相依圖、時程連線、阻塞標示與關鍵路徑；變更時重算，尊重可見性 |
| C6 整合交付 | 模板建立流程→安排時程→前置阻擋→完成前置→後續解鎖；重載／復原與越權測試 |

驗收：以模板建立至少10個任務並保持相對日期；20任務相依案例能偵測循環、正確阻擋與計算關鍵路徑。拖曳與手機日期編輯結果一致，Gate不能被改期或一般前置覆寫繞過。

需在spec定案：工作日／日曆日、順延與跨權限任務、持久化復原、父子時程規則。核心相依／排程採適合的已驗證工具，依賴與鎖版先列入plan，不直接加入新套件。

依人類指示，先讓主要前端布局／視覺接近Demo，接既有真API。對齊側欄、配色、字級間距、總覽／任務卡片、工作區／紀錄與時程；未實作模組明確標示，不增加假數據。範圍及驗收見[短規格／計畫](superpowers/plans/2026-10-09-ui1-demo-alignment.md)。UI1已交付基礎視覺，UI2已補模板／公司與展示專案；仍須按UI3–UI5逐頁對照，不將既有完成誤稱為Demo全畫面一致。

## P2d：其餘 Demo 模組（範圍索引；順序已由UI5/F1取代）

此階段按三個子專案分別spec／plan／驗收，不作單一巨型Task。

| 子專案 | 任務與交付 |
|---|---|
| D1 文件管理 | 文件清單、上傳／下載、分類、版本歷史、公司／節點／機密權限；重用B4儲存，不先做線上Office編輯 |
| D2 研發營運資料 | 依Demo範圍分批提供供應商、原料、配方版本／機密比例、採購、工單與檢驗紀錄；連結任務且記稽核，不假稱已同步ERP |
| D3 AI副手與資料分級 | 先接正式資料的規則式摘要與來源引用，再做分類／遮罩／路由政策及稽核；機密與他公司資料不得送出；模型串接須另訂規格與授權 |
| D4 整體Demo對照驗收 | 列出F1至F11的已移植／未移植差異，實跑主要業務流程，更新限制與人類試用清單 |

驗收：文件與營運內容是真實保存的業務資料；摘要可追溯且遵守可見性。未串接模型時明確標示規則式功能，不冒充真AI。

Demo其餘細節如拖曳改層級、複製子樹、通知、自訂回報欄位與機密欄位政策，要放入對應spec的功能對照表，不因本路線圖的簡寫視為已完成。刪除／批次操作需另定資料保留與引用規則。

## 不併入本輪的正式部署與外部整合

LAN／TLS部署、正式帳號生命週期、備份還原演練、AD／LDAP、真LLM、完整RAG、ERP串接與取代ERP均需要另外規劃和授權。本輪介面與功能移植不是整個正式產品路線圖結案。
