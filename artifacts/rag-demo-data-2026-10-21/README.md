# 虛構食品專案 RAG 試用資料

本包所有公司、人名、金額、規則與時程都是合成資料，僅供展示與測試；不代表真實食品安全標準、配方或業務承諾。

## 內容

- `current/`：10 份現行知識文件，8 份 TXT 與 2 份 CSV，涵蓋專案、角色、供應商、文件驗收、包裝、時程、採購、風險、會議與客服。
- `history/`：包裝規格版本 1，僅供歷史版本測試；現行規格是版本 2。
- `標準問答.md`、`questions.json`：20 題標準問答，16 題可回答、4 題應明示資料不足或尚未定案。
- `manifest.json`：文件清單、版本與 SHA256。
- `RAG虛構資料包.zip`：方便下載的文件與題庫。**不可整包遞迴匯入知識庫**。
- `evaluation.json`、[試跑結果](試跑結果.md)：實際模型輸出及 AI 內容複核；自動粗篩 16/20，內容複核 15/20 可接受，保留問題案例。

**只把 `current/` 當成現行知識來源。不要上傳題庫、標準答案或評測結果，避免答案洩漏。** 歷史文件要透過同一文件的「新版本」流程處理，不要把版本 1 和版本 2 當成兩個現行文件。

## 在本機試用

入口：http://127.0.0.1:15173 。使用公司 `food`、帳號 `yu`、展示密碼 `demo-yu`。

開啟 AI 副手 → 資料來源選「正式文件」→ 正式專案選「【虛構展示】山嵐新品 RAG 知識驗證」。

建議先問：

1. 目前的包裝規格是每箱幾包？（現行為 24 包）
2. 依首批試製數量與現行包裝規格，這批全部出貨要幾箱？請列算式。（1200 ÷ 24 = 50 箱，需核對兩份來源）
3. G2 要具備什麼才能通過？（三份文件齊備，且陳奕安簽核）
4. 已核准的備援原料供應商叫什麼名字？（仍在評選，不能編造名稱）
5. 2027 年這款產品的正式售價是多少？（資料未提供）

## 產製與隔離評測

在儲存庫根目錄執行，使用已安裝 API 相依套件的 Python：

```powershell
python artifacts/rag-demo-data-2026-10-21/build_data.py
python artifacts/rag-demo-data-2026-10-21/run_demo.py
```

評測預設使用自動清除的暫存 SQLite 與虛構帳號，實際呼叫本機 Ollama 的 `bge-m3:latest`、`qwen2.5:3b-instruct-q4_K_M`；不使用正式 PostgreSQL。會先驗證升版後、重新索引前舊版不再參與檢索，再執行 20 題。結果輸出至 `evaluation.json`。

自動檢查涵蓋答案關鍵字、必要引用、引用有效性、現行版本及拒答訊號；這些只是粗篩，不能代替人工語意評分，也不能當成完整權限或企業級品質驗收。各題保留實際答案，便於人工核對；不會為了得到全過結果而調低標準。

## 首次匯入（有資料時不要重跑）

```powershell
python artifacts/rag-demo-data-2026-10-21/run_demo.py --import-local
```

此選項明確寫入本機 15173：透過既有授權 API 新增一個獨立虛構專案，逐份上傳及索引；先上傳舊包裝版本，再升為版本 2。只讀 manifest 明列的知識文件，不讀題庫或評測答案，不重設既有資料，也不覆寫模型設定。

匯入收據儲存於 ignored `.superpowers/rag-demo-data-20261021/import-receipt.json`。只要收據已存在便拒絕重複執行；中途失敗時保留部分進度，需先檢查收據及實際文件狀態，不要直接刪收據重跑。
